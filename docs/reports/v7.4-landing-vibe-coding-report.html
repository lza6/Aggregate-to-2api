版本 v7.2.0 → v7.4（落地页） · 提交 1832c55 · 2026-09-04
范围：仅 landing/ 落地页（Vue 3.5 + Vite），未动后端 API / frontend 管理面板

上下文与动机

听风AI 已在生产环境运行（v7.2.0，腾讯云东京）。公开门面 landing/ 此前是"暗色高级落地页（无外部 CDN）"，功能齐全但视觉平、动效零、SEO 基础薄弱。本轮目标是让首屏对访客产生 惊艳第一印象，同时把 SEO 做扎实，且不破坏既有"零 CDN 依赖"原则与 CI 门禁。

直觉判断：用户把决策权完全下放并要求"放开手脚"，但 landing 是 SEO 敏感页 + 生产在跑。所以策略是 激进视觉 + 保守链路——视觉/动效/3D 激进上，但 dist 服务链路、版本一致性、og:image 等运行时契约必须零回归。

做了什么（18 文件，+1295/-158）

① 调色板演进：液态玻璃 Liquid Glass

重写 landing/src/styles/base.css 的 design token（保留旧名以兼容各 Section 引用）：

  • 底层 --bg #0a0e1a 深蓝黑（玻璃需更深底才透得出）
  • 玻璃层 --card rgba(255,255,255,0.045) + backdrop-filter: blur(20px) saturate(140%)
  • 高光 --brand #60a5fa 天蓝 + --accent #f472b6 粉珊瑚（替代原 indigo 单调主调）
  • .card::before 顶部高光反光边（液态玻璃质感核心）
  • 降级：@supports not (backdrop-filter) 退纯色；prefers-reduced-motion 全局禁动画

② 3D 背景：Three.js 粒子流场（Hero3D.vue 新建）

  • ~2200 粒子球形云分布，颜色在天蓝↔粉珊瑚间随机插值，AdditiveBlending 软光感
  • 流场运动：整体慢转 + 粒子 sin 呼吸位移；相机鼠标 parallax 缓动跟随
  • 懒加载：defineAsyncComponent(() => import('./Hero3D.vue')) + import('three') 动态导入，three 不进首屏 LCP 关键路径
  • 资源释放：onBeforeUnmount 调 renderer.forceContextLoss() 防 GL context 句柄累积（小屏↔大屏切换会重复挂载，浏览器 ~16 context 上限）
  • 三档降级：WebGL 创建失败→CSS aura；reduced-motion→只渲染静态帧；小屏粒子减半

③ 动效：motion-v（Framer 范式的 Vue 版）

  • 7 个 Section 全部 whileInView scroll reveal + stagger 延迟
  • SectionStatus chip 逐个 stagger 入场 + hover spring 抬升
  • SectionFaq/Changelog 答案展开用 AnimatePresence height 动画（exit 优雅收起）
  • SectionCta 主按钮 spring 磁吸 hover（stiffness 400 / damping 17）
  • 关键修正：Hero 首屏 h1/h2/sub 改用 CSS fade-up 而非 motion——motion 的 initial:opacity:0 在 JS 延迟/失败时会让 LCP 候选元素 h1 永久透明，对爬虫与 LCP 致命；非首屏内容才用 motion reveal

④ SEO：meta + 结构化数据

  • description 重写含核心关键词（150 字内）；keywords；robots index,follow,max-image-preview:large
  • canonical 指根；Open Graph（type/site_name/title/desc/url/locale+alternate/image）；Twitter Card summary_large_image
  • theme-color #0a0e1a + color-scheme dark
  • JSON-LD SoftwareApplication（Google 富媒体支持）+ WebSite；删掉非标准的 WebAPI（schema.org 不保证支持，纯噪声）
  • 死链修正：og:image/twitter:image 原指向 /static/tingfeng-logo.png，但后端只注册了 /static/logo.png 与 /static/logo-md.png 路由 → 改指 /static/logo-md.png

⑤ 工程：vite.config + spec 规范

  • vite.config.js 加 build.chunkSizeWarningLimit:800（three 独立 chunk ~189kb gzip 是真 3D 必然体积，诚实保留不改最小化）
  • 新建 useReveal.js 封装 whileInView 预设 + reduced-motion 降级
  • .specify/specs/004-landing-vibe-coding/ 下 spec.md / plan.md / tasks.md 三份规范文档（Spec Kit 7 阶段格式的事后追溯）

  • npm install ✓ added 20 packages in 8s（motion-v/three/@tresjs/core/@vueuse/core）
  • npm run build ✓ 414 modules, 2.75s（无错误，chunkSizeWarningLimit 警告已消除）
  • 包体积：首屏 index.js gzip 90.08kb（符合 <150kb 预算）；three 独立 chunk gzip 189.60kb 懒加载
  • vite preview + curl / → HTTP 200，首页含全部 SEO meta
  • Node 等价契约测试 9 项全绿：id=app / /assets/ / banned 0 / version 7.2.0 / og:image 路由 / lock 依赖 / SoftwareApplication / WebAPI 已删 / theme-color
  • 未跑：Python 契约测试（.venv 损坏指向不存在的 uv python 路径，系统无 python3）——已用 Node 等价覆盖；CI frontend-version-gate 会用干净环境跑 test_public_landing_is_vue3_and_no_anon_generator + TestFrontendVersionConsistency
  • 未跑：浏览器实跑 motion-v 运行时兼容（WebFetch 被 enterprise 策略阻断无法验证 schema 合规；motion-v 与 Vue 3.5.42 运行时边界需本地 npm run dev 看 console）

剩余真实风险

  • motion-v 运行时兼容：build 通过 ≠ 运行时 OK。motion-v 2.4.0 对 defineAsyncComponent + Suspense 边界处理是否有 bug，需本地浏览器烟雾测试确认
  • og:image 尺寸：复用 logo-md.png（9589 字节），未确认是否 1200×630 社交卡最佳比例。可能裁切，但不再死链
  • three 总下载量：189kb gzip 超预算但懒加载，LCP 不受影响。是真 3D 的必然代价，用户已选定
  • backdrop-filter 移动端性能：已降到 blur(12px)，但 nav 仍 blur(20px)。中端机同屏 nav+card+pill+btn 可叠 4 层 blur，建议后续压测移动端帧率
