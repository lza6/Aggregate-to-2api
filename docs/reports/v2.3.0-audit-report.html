项目自 v2.2.0 终局闭环审计后，新增了三个核心能力：

关键修复详解

1. DLQ 清空端点不匹配

问题：前端调用 POST /v1/dead-letter-queue/clear，后端定义为 DELETE /v1/dead-letter-queue。路径和方法都错了，导致 405/404 错误。

// 修复前
const res = await fetch(`${API_BASE}/v1/dead-letter-queue/clear`, { method: 'POST' });

// 修复后
const res = await fetch(`${API_BASE}/v1/dead-letter-queue`, { method: 'DELETE' });

2. Provider 响应格式不匹配

问题：前端期望 { providers: Provider[] } 数组格式，后端返回 { items: {imagefree: {...}, ...} } 字典格式。Provider 接口字段名与后端完全不匹配。

// 修复：Provider 接口对齐后端 ProviderSummary 字段
interface ProviderSummary {
  display_name: string;  // 原期望 name
  base_url: string;
  capabilities: string[];
  model_count: number;   // 原期望 models
  health_status: string; // 原期望 status
  credits: number | null;
  error_count: number;   // 原期望 error_count（一致）
}

// 前端遍历适配字典格式
const items = Object.entries(data.items ?? {}).map(([prefix, summary]) => ({ prefix, summary }));

3. WebSocket 日志路由

问题：前端日志页面连接 ws://host/v1/logs/ws，但后端未注册 WebSocket 路由。log_ws.py 的 register_ws/unregister_ws 从未被 main.py 导入或挂载。

// 修复：main.py 已导入并注册
from .log_ws import ws_log_handler, register_ws, unregister_ws

@app.websocket("/v1/logs/ws")
async def log_websocket(websocket: WebSocket):
    await register_ws(websocket)
    try:
        while True:
            data = await websocket.receive_text()
            if data == "ping":
                await websocket.send_text("pong")
    except WebSocketDisconnect:
        await unregister_ws(websocket)

4. 缓存过期值持久化错误

问题：_purge_expired 将已过期的值调用 _pending.upserts.append() 写入 DB，导致过期值被持久化而非删除。同时 _flush_pending_to_db 在无锁状态下读取 _pending，存在竞态条件。

// 修复前
if expired and self._persist_db:
    for key, value in expired:
        j = self._serialize(value)  // 过期值序列化后写入 DB
        self._pending.upserts.append((key, j, self._ttl))

// 修复后
if expired and self._persist_db:
    for key, _ in expired:
        self._pending.deletes.append(key)  // 过期值应删除

5. Worker 重复 _finish 调用

问题：permanent 错误路径中先调用 _finish(task_id, "error", ...) 标记失败，然后 break 跳出循环后再次调用 _finish（含 DLQ 后缀），产生两次 DB 写入。

// 修复前
self._finish(task_id, "error", None, str(e), t0)  // 第一次写入
last_error = str(e)
break
// 循环外：第二次写入
self._finish(task_id, "error", None, dlq_msg, t0)  // 覆盖第一次

// 修复后：移除第一次，只保留循环外的 DLQ 后缀版本

测验

1. DLQ 清空端点正确的 HTTP 方法是什么？

  • A. POST /v1/dead-letter-queue/clear
  • B. DELETE /v1/dead-letter-queue
  • C. GET /v1/dead-letter-queue/clear
  • D. PUT /v1/dead-letter-queue
正确答案: B。后端定义为 DELETE /v1/dead-letter-queue，前端之前错误地调用 POST /v1/dead-letter-queue/clear。

2. 后端 /v1/providers 返回的格式是什么？

  • A. 数组 [Provider, Provider, ...]
  • B. 对象 { providers: [Provider, ...] }
  • C. 对象 { items: { prefix: summary, ... }, count: N }
  • D. 字符串 JSON 文本
正确答案: C。后端返回 { items: { imagefree: {...}, ... }, count: N } 字典格式，前端需 Object.entries 转换。

3. 缓存过期条目的持久化操作应是什么？

  • A. 删除（deletes）
  • B. 写入（upserts）
  • C. 忽略（不处理）
  • D. 重新设置 TTL
正确答案: A。过期条目应删除而非持久化。修复前错误地调用 upserts 导致过期值被写入 DB。

4. 错误码 SYS.002 代表什么？

  • A. PROVIDER_DOWN
  • B. INTERNAL_ERROR
  • C. RATE_LIMITED
  • D. QUEUE_FULL
正确答案: D。SYS.002 = QUEUE_FULL（队列满），HTTP 状态码 429。分层格式：SYS=系统分类，002=序号。

5. 自适应重试策略中，"504 Gateway Timeout" 被分类为什么？

  • A. timeout
  • B. server_error
  • C. network_error
  • D. rate_limited
正确答案: B。504 属于 5xx 服务端错误，分类为 server_error（backoff_base=15, max_retries=4, jitter=0.4）。
