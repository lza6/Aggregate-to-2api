v3.1.0 变更卷

公益图像网关这一轮不是加皮，是把「任务卡 pending」从概率事件变成可复现、可证明、已修掉的缺陷，并补上运维能看见的仪表。

1. 背景与直觉

线上站 imagefree.tingfengai.art 已经在跑。用户要的是：慢请求能定位、worker 卡死能看见、DLQ 能真重入队、捐赠和条款能点开，并且一次调用不要把任务丢在 pending 里。

最容易被忽略的直觉：内存队列里有任务，不等于 SQLite 读连接看得到同一行。WAL + 多读连接 + 0.2s 批量写，三件事叠在一起，会在「刚入队、worker 立刻取走」的窗口里读到空行，于是 _process 直接 return，任务永久 pending。

3. 修了什么（按故障模式）

  1. WAL 旧快照：读连接 SELECT 钉死隐式事务 → isolation_level=None。
  2. flush 竞态：buffer 被 swap 走但尚未 commit，worker 以为无缓冲直接读库 → 读路径即使 buffer 空也拿同一把锁。
  3. 导入期临时 loop：DB.__init__ 禁止 asyncio.run，连接惰性创建。
  4. aiosqlite 线程泄漏：进程退出登记连接并停线程，避免 pytest 全绿后卡死。
  5. 测试隔离：禁止无条件 purge api.*；全局单例用 monkeypatch；from-import 常量双 patch。
