# 听风AI · imagefree-2ai 下一步改进指南

> **文档版本**：v1.0（基线快照 @2026-08-31）
> **当前版本**：v6.8.0 · **目标版本路线**：v7.0 → v7.5 → v8.0
> **适用对象**：后续接手的 AI（或人类工程师）按此指南执行迭代，每完成一个版本回写本节「版本回写」。
> **核心原则**：**不重构、不造轮子、在已有实现上增量打磨、每个改动必须有真实闭环与证据。**

## 0. 使用方法（先读我）

1. **本文件是「路线图 + 验收门禁」，不是逐行改码清单。** 每项优化标注了 `[文件]`、`[验证方式]`、`[风险级别]`。
2. **执行顺序**：`P0` → `P1` → `P2` → `P3`（阻塞项优先，避免「前面改 bug 后面加功能又出 bug」）。
3. 每完成一条，在对应行打 `✅` 并填 `[验证证据]`（运行的命令 + 真实输出摘要）。
4. **凡涉及改码的执行者**，改完必须运行：单测门禁 + ruff + 前端 build + 相关集成测试，未跑通禁止声称完成。
5. **凡涉及 UI 优化**，需要同时在浏览器真实点一遍（点击反馈、空态、错误态、loading 态、移动端断点）。
6. **版本回写**：每迭代一个大版本，在本节末尾追加一行，写清「版本号 / 已落地条目 / 遗留风险」。

> ⚠️ **本文件只做规划与验收，不含逐行代码。** 具体实现由你（或主程）在各步骤的 `[文件]` 里按既有风格落地。

## 1. 项目全景（建模：当前架构与事实）

### 1.1 一句话定位
> 一个把多家上游 AI 图像生成站（imagefree.net / aifreeforever / nanobanana / tryingopen / falai）聚合为统一 OpenAI 风格网关的**高并发公益服务**，配一个 React 管理面板 + Vue 公开落地页。

### 1.2 技术栈（已确认）
| 层 | 技术 | 版本/备注 |
|----|------|----------|
| 后端 | FastAPI + uvicorn | Python 3.11（uv 管理） |
| 存储 | SQLite（aiosqlite，WAL） | 队列/任务/号池/封禁/死信 全 SQLite |
| 队列 | asyncio.PriorityQueue 有界优先级队列 | 0=admin / 1=high / 2=normal |
| Token 池 | 双缓冲 Double-Buffer + 单 key 池 | 直连 + per-proxy 池 |
| 路由 | MAB-EWMA 自适应路由 + 熔断 | Score=(成功率/log10时延)×负载惩罚 |
| 上游接入 | imagefree/aifreeforever/nanobanana/tryingopen/falai | 5 个 provider |
| 前端 | React 19 + Vite 6 + React Router 7 + recharts | 管理面板（/admin，SPA，懒加载） |
| 落地页 | Vue3（/，SPA） | 公开页 |
| 运维 | docker-compose（cfsolver + api） | GHCR 镜像 CI 自动 push |

## 3. P0 阻塞项（必须最先处理，不改直接卡后续）

### P0-1 后端单测存在「Event loop is closed」线程告警
- **现象**：跑 `pytest -m "not integration and not chaos and not slow"` 时，`aiosqlite` 连接工作线程在事件循环关闭后仍被回调，产生 `RuntimeError: Event loop is closed` + `PytestUnhandledThreadExceptionWarning`。单测本身可能仍通过，但该噪声会掩盖真实非确定性失败，且可能伴随偶发崩溃。
- **根因方向**：`conftest.py` 的 `event_loop` fixture 用 session scope，但部分 DB fixture 或在 `Engine/DB` 关闭时 `aiosqlite` 线程尚未 join；跨 loop 复用造成 loop 关闭后仍有 pending 回调。
- **[涉及文件]**：`tests/conftest.py`、`api/db/core.py`、`api/lifespan.py`。
- **[验证方式]**：跑 `pytest -m "not integration and not chaos and not slow" -q` 3 次，确认无 `Event loop is closed` 告警、无 `PytestUnhandledThreadExceptionWarning`、退出码 0。
- **[风险级别]**：L2（多文件，但隔离可回滚）。
- **[状态]**：⬜ 待办

### P0-2 worker 批量循环对「任务级异常」的回收不完整
- **现象**：`_worker_batch_loop` 的 `done` 分支对 `fut.result()` 抛出的 `BaseException` 调用 `db.mark_finished(..., error, f"{exc}")`，但若 `_process` 中途已落库还是会被覆盖；且对 `pending` 分支检查 DB 时使用 `row["status"] in ("completed","error")`，而 `_process` 可能已把状态写成 `"error"` 但 `mark_finished` 尚未完成——存在微小竞态。
- **风险**：任务被重复标记或误标超时，DLQ/画廊缓存失效链可能被双写。
- **[涉及文件]**：`api/worker/engine.py`（`_worker_batch_loop`，约 399-442 行）。
- **[建议]**：`done` 分支只在 `_process` 内部未落库时才 `mark_finished`；把「是否已落库」判定提前为 `_process` 内的受控返回码，而不是事后二次 `db.get`。
- **[验证方式]**：新增/调整 `tests/test_worker_batch` 类，模拟「任务在 cancel 前完成」与「任务抛异常」两分支，断言终态唯一。
- **[风险级别]**：L2。
- **[[关联]]**：`p3-7-9-v6.6.2-closure`、`v6.8.0-p1-benchmark-deploy`。

## 4. P1 高优先级（v7.0 落地）

### P1-1 前端 `api.ts` 缺少统一错误处理中间件（重复 try/catch）
- **现象**：`fetch*` 几乎每个函数都写 `if (!res.ok) throw new Error(...)`，且错误内容不统一（有些取 `body.detail`，有些取 `body.error`，有些取 `text()`）。后续新增端点极易漏判或语义混乱。
- **[建议]**：抽一个 `apiFetch(path, opts)` 包一层：统一 `JSON.parse`、统一错误规范化（`ErrorCodes` → 中文可读文案 + 结构化 `{status, code, message}`）、统一 `caller` 追踪。`api.ts` 里所有函数改为薄封装。
- **[涉及文件]**：`frontend/src/api.ts`。
- **[验证方式]**：新增 `frontend/src/test/api.test.ts` 用例，mock `fetch` 分别返回 401/422/500 与空 body，断言统一错误对象结构；`npm run test` 通过。
- **[风险级别]**：L2（前端广泛改动，但可薄封装不破坏签名）。

### P1-2 Dashboard 并行轮询过多（8 个独立 useApi 轮询）
- **现象**：`Dashboard.tsx` 单独拉起 8 个 `useApi(..., {intervalMs})`（stats/diag/routing/sys/chatUsage/chatRemaining/authStatus/accountPool），`useApi` 各自 setInterval。页面长期开着会产生大量并发轮询，且组件卸载时 `useApi` 是否统一清理间隔导致内存/网络泄漏需核实。
- **[建议]**：抽一个 `useApi` 内部的「共享调度器」（基于 `useRef` + 单 setInterval + 任务表），或改为 `usePolling` 把多条数据合并为一个 polling 循环；同时对“仅在页面聚焦时轮询，失焦暂停”做优化。
- **[涉及文件]**：`frontend/src/hooks/useApi.ts`、`frontend/src/pages/Dashboard.tsx`。
- **[验证方式]**：`npm run build` 通过；用浏览器 DevTools Performance 面板观察长开页面的网络请求是否收敛；`vitest` 跑 `useApi.test.ts`。
- **[风险级别]**：L2。

### P1-3 后端配置导出重复与遗漏（config/__init__.py）
- **现象**：`IF_USD_PER_CREDIT` / `IF_COST_BUDGET_USD` 在第 737-742 行重复声明两次；`settings_json()` 导出的分组配置未包含 `ip_whitelist`、`trusted_proxies`、`auto_block_*`（这些在 security 模块里但 Model 未对齐）。`/v1/meta` 可能看不到完整风控配置。
- **[建议]**：清理重复声明；给 `DBSettings`/`SecuritySettings` 补齐风控字段；`settings_json` 增加 `"""security_list""”；文档同步 `deploy/.env.example`。
- **[涉及文件]**：`api/config/__init__.py`、`deploy/.env.example`、`README.md`。
- **[验证方式]**：`pytest` 新增 `test_config_validate` 用例，断言 `settings.settings_json()` 含 `security.ip_whitelist` 等字段。
- **[风险级别]**：L1。

### P1-4 网关层缺一层「统一任务编目」能力（任务查询无全局聚合）
- **现象**：入口 `GenerateRequest` 有 `model` / `aspect_ratio` / `prompt` / `priority` / `download` / `idempotency_key`；但任务表只有 `tasks`。不同 provider（imagefree vs 非 imagefree）走不同路径（`engine.submit` vs `_dispatch_generate` 分支），导致 `/v1/tasks` 列表没有统一区分「任务类型」字段，运维排查困难。
- **[建议]**：`task_to_public` 增加 `task_type`（txt/img2img/txt2vid/img2vid）与 `provider`（路由到哪个别称），并提供 `/v1/tasks?kind=` 过滤。
- **[涉及文件]**：`api/db/queries.py`、`api/routes/tasks.py`、`frontend/src/pages/Tasks.tsx`。
- **[验证方式]**：集成测试 `test_async_flow` 扩展断言 `task_type` / `provider`。
- **[风险级别]**：L2。

## 5. P2 中优先级（v7.1 / v7.2 落地）

### P2-1 画廊签名 URL 缺少「前端自动过期刷新」
- **现象**：`Gallery.tsx` 用签名 URL（`exp`+`sig`）访问图，但前端在 `exp` 到了之后不会主动重新签；用户点开长时打开的老图会 403 撞墙。
- **[建议]**：Gallery 组件对每个 `image_url` 解析 `exp`；`exp` 提前 5s 用 `signGallery` 重签或触发 `onGalleryFail` 走密码重试流。已有 `signGallery` 接口直接复用。
- **[涉及文件]**：`frontend/src/components/Gallery.tsx`。
- **[验证方式]**：`vitest` 新增用例模拟 exp 到期触发重签；浏览器实测长列表下滑不 403。

### P2-2 慢日志面板缺失（后端已采集 `SlowSample`，前端无展示）
- **现象**：后端 `slow_log.py` 已记录 `SlowSample`（queue/wait_token/solve/upstream/retry/submit/poll 分段），`Diagnostics.slow_log` 也返回 count/avg/max/stage，但前端 Dashboard 未展示；也没有可下钻的慢请求明细页。
- **已核实（避免误判）**：`/v1/slow`（`api/routes/admin.py:568`）与 `/v1/slow/view`（`admin.py:635`，返回 `api/static/slow.html` 静态看板，内部 `fetch("/v1/slow")`）**后端确实已存在**。因此本项不是「补后端端点」，而是「把慢请求画像接入 React 管理面板」——当前慢看板是脱离 React 应用的独立静态 HTML，与 `/admin` 体验割裂、无统一样式/导航。
- **[建议]**：在 React 面板新增 `Slow.tsx` 页（复用现成 `/v1/slow` JSON），Dashboard 增加「慢请求画像」摘要卡片 + 下钻入口；保留 `/v1/slow/view` 静态页做向后兼容，新页走 `/admin/slow` 路由。
- **[涉及文件]**：`frontend/src/pages/`（新增 Slow.tsx）、`frontend/src/App.tsx`、`frontend/src/api.ts`（新增 `fetchSlow()`）；后端 `api/routes/admin.py` 无需改（端点已存在）。
- **[验证方式]**：`npm run build` 通过；浏览器访问 `/admin/slow` 看到分段表；`vitest` 断言 `fetchSlow` 数据形状。
- **[风险级别]**：L1（纯前端新增只读页，复用既有端点）。

### P2-3 CORS / CSP 安全头可从「全放行」收紧到「最小可用」
- **现象**：`api/main.py` 的 CORS 白名单默认 `*`；加中间件时未加 `Strict-Transport-Security` / `X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy`。
- **[建议]**：加一个 `SecurityHeaders` 中间件，生产环境注入最小化 CSP；`main.py` 里默认可通过 `IF_CORS_ORIGINS` 收紧。**注意**：这一步涉及生产行为，需单独在「需确认后执行」边界评估，应提供回滚。
- **[风险级别]**：L3（安全边界，须先影响分析 + 红队评估）。

## 9. 根因分析（RCA）清单

> 若某问题**第二次出现**，按此流程强制做 RCA，禁止只打补丁。

| 问题 | 首次出现时 | 第二次出现时 |
|------|-----------|-------------|
| 任务卡 pending | 排查入口引擎是否 `stale` / 队列深度 / token 池水位 | 确认是否 WAL autocommit 旧快照（见记忆 sqlite-wal-autocommit） |
| 健康检查降级 | 看 `cf_solver` / `solver_status` 表 | 确认是否 solver 熔断（`solver_guard` `circuit_open`）、是否 IdleTimeout 节点被误判 |
| DLQ 任务无法重试 | 看 `retry` 是否走 `requeue_dlq_task` | 确认 `IF_DLQ_REQUEUE` 是否开启，否则 retry 只标记不重入 |
| 前端 403 画廊 | 看是否为签名 URL exp 过期 | 确认 `IF_GALLERY_SIGNING_*` 配置是否生效 |
| 限流过度拦截正常用户 | 检查 `IF_REQUESTS_PER_MINUTE`/`token capacity` 是否过小 | 检查 `trusted_proxies` 是否未包含真实反代，导致 XFF 处理异常 |
| Config 生效异常 | 查看 `env` 空串是否被 `Settings._drop_blank_env` 过滤 | 确认字段是否在 `settings_json()` 中暴露 |
| 代理池不可用 | 查看 `ProxyPoolSnapshot.available`、`residential/free` 分布 | 确认 `IF_PROXY_USE_COOLDOWN_MAP` 是否过长、`24h` 重置逻辑是否被误触发 |

## 13. 安全底线（执行前必读）

1. **任何新改动不得引入硬编码密钥**（API key / pass / token）到源码或测试。
2. **写操作**（封禁/解封/DLQ 重试/清空/画廊签）必须走管理 Key 鉴权边界，禁止在匿名只读请求带 Key。
3. **CORS / CSP 收紧**属于 L3，务必先做影响分析 + 红队，并提供回滚方案。
4. 若发现问题安全漏洞：立即停止 → security-reviewer 代理 → 修复 CRITICAL → 轮换暴露密钥。
5. 画廊签名 URL 仅校验 `exp` 不绑 IP（CGNAT/代理下 IP 漂移会误杀），**不要修改**该边界。
