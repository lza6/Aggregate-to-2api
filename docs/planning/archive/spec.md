# 规范说明书：UI/UX 体验与移动端全链路改进 (v6.3.3)

## 1. 业务背景与问题定义
当前系统已作为高并发多提供商 AI 图像生成网关在线上运行。但在移动端窄屏（特别是 375px 的 iPhone SE 设备）以及长耗时生图场景下，存在以下体验痛点：
1. **窄屏溢出与布局挤压**：在 ≤375px 窄屏视口下，顶部状态栏徽章、卡片数值与柱状图出现横向溢出与内容重叠。
2. **长耗时出图缺乏感知**：生图平均耗时在 15~40 秒之间，原前端仅展示静态“加载中”文字，缺乏阶段细分，导致用户产生“请求卡死/白屏”的焦虑。
3. **错误提示不可行动**：上游并发限流（429）或未配置 API Key（401）时，仅提示生硬的英文或通用失败，缺乏自动故障转移提示与一键复制示例。
4. **管理端日志无感知断线**：WebSocket 网络抖动断开后不会自动指数退避重连，且缺乏心跳指示器，管理员难以判断日志流是否正常。

## 2. 目标与非目标
- **目标**：
  - 完美适配 375px/480px 窄屏，彻底消除溢出与重叠；
  - 实现 4 阶段渐进式生图进度步进条（排队 $\to$ Turnstile 求解 $\to$ 上游渲染 $\to$ 下载分发）；
  - 错误提示场景化：自动识别限流并提示平滑重试；未配置 Key 提供一键复制 cURL 命令；
  - 增强 WebSocket 健壮性：指数退避重连（最大 10s）、重连 Spinner 动画、10s 心跳保活与指示器；
  - 构建端到端自动化测试并生成自包含变更报告。
- **非目标**：
  - 不修改核心队列调度算法与 Token 轮换逻辑；
  - 不引入大型第三方 UI 框架依赖。

## 3. 验收标准 (Acceptance Criteria)
1. **AC-1**：在 375px 视口下，`api/docs.html` 与 React 管理后台完全自适应，水平滚动条仅在代码块或宽表格内出现，主容器无全局水平溢出。
2. **AC-2**：在线生图触发后，进度条按任务状态 `pending` $\to$ `processing` $\to$ `completed` 动态点亮对应节点与连接线。
3. **AC-3**：触发 429 报错时明确展示“当前提供商繁忙，已为您自动切换至备用引擎”；401 时展示一键复制示例按钮并支持安全复制 fallback。
4. **AC-4**：WebSocket 断开时状态徽章变为“正在重连中”，连接恢复后重置计数器；心跳时间戳正常滚动。
5. **AC-5**：全量测试套件通过率 100%，前端打包 0 编译错误。
