## 1. 高优（P0）——破圈层：让能力走出去

### P0-1 MCP Server 升级为官方 Streamable HTTP + 资源/提示能力（对外生态接入）

**现状**：`api/mcp/server.py` 已是标准 MCP JSON-RPC 2.0（`POST /v1/mcp`，tools/list + tools/call，`PROTOCOL_VERSION="2025-06-18"`，五工具 skills_list/skills_get/dag_plan/dag_status/generate_image，见 `tools.py:110-180`），但**协议形态是"单端点请求-响应"**：无 `resources/list`、`prompts/list` capabilities 声明，无 SSE/流式响应，外部 MCP client（Claude Desktop / Cursor / 微信 agent）无法直接按官方 Transport 接入。这是"造了 MCP 但没通电流"。

**目标（破圈核心）**：把 `/v1/mcp` 升级为官方 **Streamable HTTP Transport** 兼容端点，让任何 MCP client 能开箱即连，用自然语言驱动听风AI 生图/对话/DAG。这是从"内部 agent 专属工具"到"对外可接入智能体生态"的范式跃迁。

**落地步**：
1. 能力声明补全：`initialize` 响应 `capabilities` 增加 `{resources:{}, prompts:{}, tools:{}}`（保持 `tools` 下兼容）；`resources/list` 暴露只读资源（如 `memory://latest`、`audit://today`），`prompts/list` 暴露 3-5 个模板（`image-from-prompt`/`dag-explore`/`cost-review`）。
2. Streamable HTTP 适配：对齐 `2025-06-18` 规范——`Accept: application/json, text/event-stream` 时响应走 SSE 分帧；`Mcp-Session-Id` 会话头支持（缺省无状态返回，兼容 Keep-alive）；`DELETE` 谓词结束会话。零事件时降级为当前单响应（向后兼容，不破坏既有 5 工具调用方）。
3. `generate_image` 工具补齐真实异步任务路径：工具调用模式返回 `{task_id, status: queued}`，再由 `resources` / 新工具 `task_status` 轮询（幂等），避免 MCP 单请求内阻塞 6-30s 上游生成。
4. 前端 ApiGuide 页补"MCP 连接配置"卡片：给出 Claude Desktop / Cursor 各一行 JSON 配置样例 + `IF_MCP_ENABLED=1` 开启说明。
5. 测试：`tests/test_mcp_server.py` 扩展——SSE 分帧时 content-type/协议断言、capabilities 声明断言、session 头幂等、工具排队返回后 `task_status` 轮询 3 次收敛。

**验收**：`pytest tests/test_mcp_server.py -q` 全绿；`curl -N -X POST /v1/mcp -H "Accept: text/event-stream"` 返回 SSE 帧；Claude Desktop 配置连接可在聊天里完成一次受控生图（`IF_MOCK_UPSTREAM=1`）。
**影响半径**：L2（单路由 + 工具层增量，新增协议分支不删旧路径）。
**新增开关**：`IF_MCP_STREAMABLE`（缺省 1，极低版本兼容风险）。

### P0-2 聊天 tools 真实安全执行回路（网关侧执行，非仅转发）

**现状**：`api/routes/chat.py` 全程"转发"模型：`_result_parts` 解析上游 `tool_calls`（`chat.py:192`），流式 `_openai_chunk` 原样转发 tool_call 事件（`chat.py:349-377`），`finish_reason=tool_calls` 后**网关不执行、不回填 `tool` 角色消息**——即用户通过聊天请求"帮我生成一张猫的图"时，只有模型工具声明，没有产生图片。anatomy 已标"P1-A 待补"。

**目标**：在指令级（`request.tools` 缺失且用户意图含生图/查技能/走 DAG 时）或在工具声明白名单命中时，网关侧安全执行工具并把结果以 `role: tool` 消息回填，续跑一次模型汇总。工具白名单 = 已有 MCP 五工具（skills_list/skills_get/dag_plan/generate_image）+ `memory_search`（只读）。复用 P1-8 护栏：`guard_paid_call("tool", name)` + `is_destructive_command` 黑名单先行拒绝。

**落地步**：
1. `chat.py` 增 `_run_local_tool(tool_name, arguments) -> dict`：映射到 `api/mcp/tools.py` 内 `find_tool` + `guard_and_run`（**同一份实现，不复制逻辑**——from-import 用运行时读模块，勿值拷贝踩坑）。
2. 执行策略开关：`IF_CHAT_TOOL_LOOP`（缺省 0）→ 开启后：检测 tool_calls 里命中白名单的名称 → 逐条执行 → 拼 `{role:"tool", tool_call_id, content: json}` → 追加进 messages 再调一次上游（单轮，防死循环；`IF_CHAT_TOOL_MAX_TURNS=2` 兜底）。
3. **鉴权边界**：聊天端点受 `IF_API_KEYS` 保护（已实现）；生图工具走 `guard_paid_call("generate_image")` 预算门禁（enforce 402 回填为"无权限"文本而非静默成败）。
4. 测试：`tests/test_chat_tool_loop.py`——命中白名单执行并回填 tool 消息、黑名单拒绝明文、预算 enforce 402、`IF_CHAT_TOOL_LOOP=0` 走旧纯转发零行为变化。

**验收**：新增测试全绿 + 既有 `test_chat_stream_frames.py` 不回归；E2E 聊天里 `帮我生成一张猫图`（Mock）最终消息含图片占位 result。
**影响半径**：L2（chat.py 主路径，纯增量分支 + 开关缺省关，可回滚）。
**新增开关**：`IF_CHAT_TOOL_LOOP`（缺省 0）、`IF_CHAT_TOOL_MAX_TURNS`（缺省 2）。

### P0-4 任务实时进度可视化 + 幂等取消 + 一键重试
