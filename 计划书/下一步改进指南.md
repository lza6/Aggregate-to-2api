## 一、 项目现状体检与第一性原理深度剖析

### 1.1 现状核心能力与资产梳理
当前项目已具备坚实的企业级基础设施（v3.1.0）：
1. **统一 API 网关**：封装 OpenAI 风格 `/v1/images/generations`，支持 txt2img、多上游模型路由与降级。
2. **多上游接入**：已支持 `imagefree`、`aifreeforever`、`minimaxh3`、`nanobanana` 等提供商。
3. **高并发底座**：有界优先级队列（PriorityQueue）、自适应动态 Worker 弹性缩放（4-16）、Turnstile Token 预取池、SQLite WAL 读写分离与连接池。
4. **可观测与运维**：Prometheus 指标、慢请求画像（Slow Log）、心跳巡检（Worker Health）、死信队列（DLQ）、磁盘日志滚动、React 管理后台。

### 1.2 第一性原理剖析：SaaS 平台的核心矛盾
从第一性原理分析，AI 图像生成 API 网关的核心价值与瓶颈在于：
- **用户本质诉求**：**极致出图速度（低延迟）**、**高成功率（零中断）**、**高质量图像呈现与快捷导出**、**透明的任务进度感知**。
- **核心系统矛盾**：
  1. **上游不确定性 vs 用户高 SLA 期望**：逆向上游存在人机校验拦截（Turnstile 5s+）、频繁风控封号、网络链路抖动、偶发限流（429）。
  2. **短轮询网络浪费 vs 客户端实时性要求**：传统客户端高频轮询 `/v1/tasks/{id}` 导致服务端无效 QPS 膨胀 90% 以上。
  3. **SQLite 单写锁 vs 高吞吐写入峰值**：当并发 RPS 突破 300+，即便 WAL 模式下写事务排队也会引发轻微事务阻塞。
  4. **管理员运维复杂性 vs 小白极简操作**：号池健康度、代理失效、上游延时缺乏一键自愈与智能化干预手段。

## 三、 核心模块演进方案与落地代码示例

### 1. 智能多维度路由网关与自适应调度
#### 【痛点分析】
原有路由主要依赖静态权重或单一成功率，在上游网络突发抖动、Turnstile 求解器排队时，容易将流量继续打入慢节点。
#### 【v3.2+ 优化方案】
引入 **MAB-Epsilon-Greedy-Decay + EWMA (指数加权移动平均时延) 联合路由算法**：
- 结合「近 30 秒平均响应时间」、「近 10 次调用成功率」、「当前可用 Token/账号余量」实时加权打分。
- 支持平滑故障降级（Failover Matrix）：当首选提供商熔断时，0ms 自动静默切换至备选提供商。

#### 【关键设计方案与结构】
```python
# api/adaptive_router.py (方案骨架设计)
import time
import math
from typing import Dict, List, Optional
from dataclasses import dataclass, field

@dataclass
class ProviderNodeStats:
    provider_id: str
    success_count: int = 0
    failure_count: int = 0
    ewma_latency_ms: float = 2000.0  # 初始预估 2s
    in_flight_requests: int = 0
    circuit_state: str = "CLOSED"    # CLOSED, OPEN, HALF_OPEN
    circuit_open_until: float = 0.0

class AdaptiveRouter:
    def __init__(self, alpha: float = 0.2, explore_rate: float = 0.05):
        self.alpha = alpha  # EWMA 平滑系数
        self.explore_rate = explore_rate
        self.nodes: Dict[str, ProviderNodeStats] = {}

    def record_result(self, provider_id: str, latency_ms: float, is_success: bool):
        stats = self.nodes.setdefault(provider_id, ProviderNodeStats(provider_id=provider_id))
        stats.in_flight_requests = max(0, stats.in_flight_requests - 1)
        
        if is_success:
            stats.success_count += 1
            stats.ewma_latency_ms = (self.alpha * latency_ms) + ((1 - self.alpha) * stats.ewma_latency_ms)
            if stats.circuit_state == "HALF_OPEN":
                stats.circuit_state = "CLOSED"
        else:
            stats.failure_count += 1
            # 连续失败触发熔断 (如失败率 > 50% 且样本数 >= 5)
            total = stats.success_count + stats.failure_count
            if total >= 5 and (stats.failure_count / total) > 0.5:
                stats.circuit_state = "OPEN"
                stats.circuit_open_until = time.time() + 30.0  # 熔断 30 秒

    def select_best_provider(self, available_providers: List[str]) -> str:
        now = time.time()
        valid_candidates = []
        
        for pid in available_providers:
            stats = self.nodes.setdefault(pid, ProviderNodeStats(provider_id=pid))
            # 检查熔断恢复
            if stats.circuit_state == "OPEN":
                if now > stats.circuit_open_until:
                    stats.circuit_state = "HALF_OPEN"
                else:
                    continue
            valid_candidates.append(pid)

        if not valid_candidates:
            return available_providers[0]  # 兜底返回

        # 计算综合评分 Score = (成功率 / (log(EWMA_Latency) + 1)) * 负载惩罚
        def calculate_score(pid: str) -> float:
            st = self.nodes[pid]
            total = st.success_count + st.failure_count
            success_rate = (st.success_count + 1.0) / (total + 2.0)  # Laplace 平滑
            latency_factor = math.log10(max(100.0, st.ewma_latency_ms))
            load_penalty = 1.0 / (1.0 + 0.1 * st.in_flight_requests)
            return (success_rate / latency_factor) * load_penalty

        return max(valid_candidates, key=calculate_score)
```

### 2. SSE 真实双向全双工推流与断线补偿机制
#### 【痛点分析】
生成一张高质量图片通常耗时 5~15 秒，客户端（如聊天机器人、UI界面）需要展示：`排队中 (第 2 位)` -> `Turnstile 求解中` -> `上游生成中 (45%)` -> `完成/图片下发`。
#### 【v3.2+ 优化方案】
实现标准的 **Server-Sent Events (SSE) 事件流体系**：
- `/v1/tasks/{id}/events` 端点支持标准事件类型：`status`、`progress`、`log`、`result`、`error`。
- 支持 `Last-Event-ID` 断线重连补偿机制，避免网络闪断丢失已生成成功的图片信息。

#### 【关键设计方案与结构】
```python
# api/sse_events.py (方案骨架设计)
import asyncio
import json
from typing import AsyncGenerator
from fastapi import APIRouter, Request, HTTPException
from fastapi.responses import StreamingResponse

sse_router = APIRouter(prefix="/v1/tasks", tags=["SSE"])

class TaskEventHub:
    def __init__(self):
        self._subscribers: dict[str, list[asyncio.Queue]] = {}

    def subscribe(self, task_id: str) -> asyncio.Queue:
        q = asyncio.Queue(maxsize=50)
        self._subscribers.setdefault(task_id, []).append(q)
        return q

    def unsubscribe(self, task_id: str, q: asyncio.Queue):
        if task_id in self._subscribers:
            if q in self._subscribers[task_id]:
                self._subscribers[task_id].remove(q)
            if not self._subscribers[task_id]:
                del self._subscribers[task_id]

    async def publish_event(self, task_id: str, event_type: str, data: dict):
        if task_id not in self._subscribers:
            return
        payload = {
            "event": event_type,
            "data": data,
            "timestamp": time.time()
        }
        for q in list(self._subscribers[task_id]):
            try:
                q.put_nowait(payload)
            except asyncio.QueueFull:
                pass

hub = TaskEventHub()

async def event_generator(request: Request, task_id: str) -> AsyncGenerator[str, None]:
    queue = hub.subscribe(task_id)
    try:
        # 发送初始连接成功事件
        yield f"event: ping\ndata: {json.dumps({'msg': 'connected', 'task_id': task_id})}\n\n"
        
        while True:
            if await request.is_disconnected():
                break
            try:
                # 15s 心跳保活
                event = await asyncio.wait_for(queue.get(), timeout=15.0)
                yield f"event: {event['event']}\ndata: {json.dumps(event['data'])}\n\n"
                if event['event'] in ('result', 'error'):
                    break
            except asyncio.TimeoutError:
                yield "event: ping\ndata: {}\n\n"
    finally:
        hub.unsubscribe(task_id, queue)

@sse_router.get("/{task_id}/events")
async def task_events_endpoint(request: Request, task_id: str):
    return StreamingResponse(
        event_generator(request, task_id),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no"
        }
    )
```

### 3. 号池自动化、生命周期智能轮换与反风控防护体系
#### 【痛点分析】
部分提供商（如 minimaxh3/nanobanana）账号有每日限额或点数，频繁并发可能触发 IP 封锁或会话吊销。
#### 【v3.2+ 优化方案】
- **账号配额智能平滑分配**：每个账号维护 `quota_remaining` 与 `cooling_until`，并支持每日 UTC 00:00 自动重置与心跳签到。
- **动态指纹对抗 (Fingerprint Evasion)**：轮换 Client JA3/JA4 指纹特征与 User-Agent，结合住宅代理 IP 智能绑定会话。
- **注册速率自适应**：当号池健康可用率低于 30% 时，触发异步后台 Worker 阶梯注册（每分钟不超过 3 个，避免上游整段封杀）。

### 4. SQLite 极端高并发下的写入缓冲与内存快照缓存 (Write-Coalescing)
#### 【痛点分析】
尽管已开启 `PRAGMA synchronous = NORMAL` 与 `WAL` 模式，但在 500+ 并发瞬时任务状态更新时（例如排队状态变更、心跳打点），直接打 DB 仍可能产生微小锁等待。
#### 【v3.2+ 优化方案】
- **内存写聚合队列 (Write-Coalescing Buffer)**：
  - 任务状态高频变更先存入内存字典（提供 0ms 查询），后台固定 100ms 批量写入 DB。
  - 单条关键任务完成（`COMPLETED` / `FAILED`）同步写入，普通状态（`PENDING` -> `PROCESSING`）走批量聚合写入。

### 5. 前端 React 管理控制台与交互体验重构 (UI/UX 跃迁)
#### 【痛点分析】
现有管理后台功能强大但信息密度稍高，移动端适配及小白用户易用性仍有提升空间。
#### 【v3.2+ 优化方案】
1. **全局快捷键与命令面板 (Command Palette `Ctrl+K`)**：一键快速检索任务、查看提供商健康度、触发清空缓存与强制签到。
2. **画廊无级缩放与图片参数深度复用**：点击任意作品不仅可无损导出，还可一键「复制 Seed & Prompt 并重填到调试器」。
3. **上游节点延迟拓扑雷达图 (Latency & Topology Visualizer)**：以动态热力图/雷达图直观呈现各上游提供商的实时稳定性。
4. **小白一键诊断助手**：提供「一键自检」卡片，若 cf_solver 异常或代理超时，直接展示红黄绿状态并给出具体修复命令。

## 六、 旧版本残留清理与技术债务防御清单

在实施上述升级时，必须坚持**精准修改、不造冗余轮子**的原则，并对历史遗留进行规范化清理：
1. **清理废弃测试与临时文件**：定期清理 `tests/` 中因历史重构遗留的冗余 mock 文件，清除 `.pytest_cache`、`htmlcov` 及根目录临时 dump 文件。
2. **保持单例单点导入规范**：对 `config.py` 与 `db.py` 严格保持模块级向后兼容，所有环境变量均保持 `IF_*` 前缀。
3. **数据库字段向前兼容**：新增字段（如 `tasks.sse_pushed` 或 `accounts.last_checkin`）必须在 `db.py` 的 `_apply_migrations` 中使用 `ALTER TABLE ... ADD COLUMN` 进行安全幂等递增迁移，严禁破坏既有数据。
4. **前后端产物构建隔离**：前端构建产物严格输出至 `frontend/dist`，禁止将临时源码打包入生产镜像。
