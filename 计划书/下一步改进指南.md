## 2. 当前项目基线

### 2.1 项目目标与用户

- **目标**：聚合多家上游 AI 图像/对话服务，统一 OpenAI 风格 `/v1/*` 接口；提供生成任务队列、号池/代理池、管理面板。
- **目标用户**：开发者（调用 API）+ 站长/运营（管理面板）+ 公益普通用户（落地页直接生成）。
- **核心使用场景**：文生图/图生图/聊天补全/DAG 多步任务编排。

### 2.2 技术栈

- **后端**：Python 3.11+ / FastAPI / uvicorn / httpx / aiosqlite / pydantic-v2 / prometheus-client / OpenTelemetry（可选）。依赖以 `pyproject.toml` + `requirements.txt` 为准。
- **前端**：React 19 + TS 5.7 + Vite 6 + react-router-dom 7 + recharts + Vitest 4（管理面板 `frontend/`）；Vue3 + Vite + three + motion-v（落地页 `landing/`）。
- **外部求解器**：`cf_solver`（Turnstile 求解器，端口 8001），聊天/生图主链路依赖；桌面版已 PyInstaller 打包进单文件全栈（`desktop/backend/uvicorn.exe` 30MB sidecar）。
- **桌面版**：Tauri 2.x（Rust 主进程）+ React19 复用前端 dist + sidecar 托管 uvicorn（`desktop/src-tauri/src/lib.rs`），NSIS 安装包，CSP 收紧（connect-src 仅 127.0.0.1:8100）。
- **数据层**：SQLite（aiosqlite）—— `data/imagefree.db`（任务/审计）、`data/account_pool.db`（号池）、`data/email_registry.db`（邮箱池）、`data/edit_leases.db`（图生图互斥租约）、`data/dag_runs.db`（DAG run 持久化）、`data/vectors.db`（向量存储）。

### 2.4 主要入口与运行路径

- **请求入口**：`POST /v1/generate` → `routes/generate.py` → 校验 → SQLite 入库 → 优先级队列 → 立即返回 task_id；`/v1/generate/async` 异步轮询。
- **DAG 入口（v9.0.0+）**：`POST /v1/agent/dag/run`（提交即拓扑校验→`background.spawn` 执行→SQLite 持久化）→ `GET /v1/agent/dag/{run_id}`（查询状态）→ `GET /v1/agent/dag`（历史列表，v10.0.0 分页/状态过滤）→ `POST /v1/agent/dag/plan`（自然语言→DAG）。
- **聊天入口**：`/v1/chat/completions`、`/v1/messages`（`IF_API_KEYS` 保护，三传法）。
- **agent 体系**：`/v1/agent/intent`、`/v1/agent/skills`、`/v1/agent/memory`、`/v1/agent/memory/observe`、`/v1/agent/health`。
- **桌面版入口**：Tauri 主进程（`desktop/src-tauri/src/lib.rs`）启动时拉起 uvicorn:8100（sidecar `desktop/backend/uvicorn.exe` 或系统 python）+ 可选 cf_solver，健康探测 `GET /v1/healthz` 就绪后显示主窗口，关闭时按 pid 回收子进程；`backend_status` 命令暴露给前端。

## 16. Red Team 事前反证（六个月后 v11.0.0 计划失败倒推）

| # | 未验证假设 | 失败场景 | 触发条件 | 失败成本 | 最小证伪实验 | 结果如何影响路线图 |
|---|---|---|---|---|---|---|
| 1 | 「reactflow 兼容 React 19」 | 可视化页拖期 2 周 | reactflow v12 与 React 19 有 peer 冲突 | 高（V11-V3 是主线） | 第 0 波先建 demo 页试装 reactflow，1 小时内确认 | 不兼容 → 方案 C 列表兜底，V11-V3 降级 |
| 2 | 「MCP SSE 传输仍受官方支持」 | MCP server 化后 SSE 传输被弃用 | SDK 版本演进弃用 SSE | 中 | V02 最小实验先连 Claude Code | 不可用 → 改 stdio + 自定义 SSE 双轨 |
| 3 | 「SQLite 写 DAG run 不卡任务队列」 | 任务写入与 dag 写入争锁 | 高频 DAG 提交 + 队列并发 | 中 | 压测 `scripts/loadtest.py` 混跑 | 争锁 → dag 写独立 db 文件（已用 `data/dag_runs.db`，V01 复验） |
| 4 | 「DAG 深化层不回归引擎」 | 引擎状态机被意外破坏 | 改 `dag.py` 加 reflect/condition 字段 | 高 | 每子项后跑 `pytest tests/test_agent_dag.py`（29 用例） | 回归 → 冻结引擎 API，深化层只加可选字段 |
| 5 | 「公益开放 DAG 不会被刷」 | 上游免费额度被恶意刷爆 | 无额度闸 + 无 Key 可提交 | 高 | 监控 `/metrics` dag 提交速率 | 有风险 → S-1 限流先行（V17） |

**结论**：
- 可以直接开始：V01/V05/V06/V07/V08/V09/V10/V13/V16/V17（不依赖实验）
- 应先实验再实施：V11（reactflow 兼容）/V02（MCP SDK 形态）
- 应降低优先级：V12（chat RAG 影响面大，先 core 后接）/6.2-f 人机协作（P3 第二期）/V15 桌面版自动更新（L3 需签名服务器）
- 当前不建议实施：storage Redis 集群化（L3 生产灰度，无容量证据）、Cloudflare 免费层接入（L3 待授权）
