## 0. 执行总纲（先读这一章）

### 0.1 三条铁律（违反任一条即视为失败）

1. **不重构**：任何改动不得改变现有模块的公共接口签名（函数名、参数顺序、返回结构）。`api/account_pool.py`、`api/worker/engine.py`、`api/adaptive_router.py` 等已有调用方密集的核心模块，只允许**内部实现替换**与**追加方法**，不得删除/重命名既有方法。拆分大文件时，旧路径必须保留 `from .new_module import *` 兼容垫片（参考 v7.3 `email_pool.py` 1315→386 + email_sources/ 的拆分先例，见 `docs/verification-log.md` 第 29 行）。

2. **不造轮子**：动手前先 `graft ask "<task>"` 或 `rg "<功能词>"` 搜现有实现。本项目已有：
   - 分布式锁 + 滑窗限流的 Redis 适配器 `api/storage/`（**已造好未接线**，见 `docs/architecture-evolution.md` 第 31 行 P0-3 标注）—— v8.0 的限流增强**直接接线**，不重写。
   - `api/background.py` 的 `spawn()` 强引用集（v7.7 已落地）—— 所有新后台任务**直接复用**，不用裸 `asyncio.create_task`。
   - `api/solver_guard.py` 多节点联邦（v7.x 已支持）—— cf_solver 扩容只加节点，不改代码。
   - `api/adaptive_router.py` 的 SQLite 持久化 + warm 冷启动（P3-1 已实现）—— 路由增强只调参，不重写引擎。

3. **先测后改**：每条改动必须先写/改测试（RED）→ 跑测试见红 → 实现（GREEN）→ 重构（IMPROVE）→ 跑全量验证。**禁止**「先改代码再补测试」。本指南第 10 章给出每条改动的 TDD 清单。

## 1. 第一性原理：这个项目的本质是什么

### 1.1 一句话本质

> **听风AI 是一个「上游免费 AI 能力的聚合与再分发网关」，它的核心价值 = 把 N 家上游的「人机验证 + 账号额度 + IP 风控 + 异步生成」四重摩擦，压缩成开发者侧的一个 `POST /v1/generate` 同步调用。**

### 1.2 推论：改进的发力点在哪

从本质出发，这个项目的**护城河**与**瓶颈**完全一致——都在「四重摩擦的消除效率」上：

| 摩擦源 | 当前解法 | 改进发力点 |
|--------|---------|-----------|
| 人机验证（Turnstile） | cf_solver 单节点 6.13s/次 | 多节点联邦 + 预取池水位预测（P1-2） |
| 账号额度 | nanobanana 每日签到 + 号池 FSM | FSM 自愈 + 余额预测 + 跨提供商借用（P1-3） |
| IP 风控 | 代理池轮换 + 每日限额 | 代理健康评分 + 住宅代理智能调度 + 出口粘滞（P1-4） |
| 异步生成 | PriorityQueue + Worker 4-16 | 自适应扩缩容算法升级 + 优先级动态调整（P1-5） |

**反推**：任何与「四重摩擦消除」无关的改进都是次要的。例如换 Postgres、上 Kafka、分库分表——`docs/architecture-evolution.md` 第 16 行已结论性指出「当前都是负优化」。本指南**不**纳入此类过度工程。

### 1.3 产品定位的三个不变量

迭代过程中，以下三个不变量**不得破坏**（破坏即产品变质）：

1. **公益开放**：生图/聊天不限 Key，仅 per-IP 限速（v7.7.6 决策，见 `docs/verification-log.md` 第 89 行）。任何改进不得引入「生图必须 Key」的回归。
2. **单机可部署**：`docker compose up -d` 一键起（`deploy/docker-compose.yml`）。任何改进不得强制依赖外部服务（Redis/Postgres/Kafka）—— 外部依赖必须是**可选增强**（`IF_STORAGE_BACKEND=redis` 开关，缺省走内存/SQLite）。
3. **真实闭环**：声称「完成」必须附 `pytest`/`vitest`/`build` 真实输出。禁止 TODO/Mock/假数据冒充生产（`CLAUDE.md` 真实闭环铁则）。

## 3. RIPER-5 协议执行计划

本指南采用 RIPER-5 五阶段协议（Research → Innovate → Plan → Execute → Review），每阶段有完成标准与回退机制。

### 3.1 Phase 1: Research（已完成，即本指南第 1-2 章）

- ✅ 代码考古：见 §2 现状画像（已用 `find`/`wc`/`Read` 扫描全部 api/ frontend/ landing/ tests/）
- ✅ 架构分析：见 §1 第一性原理 + `docs/architecture-evolution.md`

### 6.2 P1-2：cf_solver 多节点联邦扩容

**现状**：`api/solver_guard.py` 已支持多节点联邦 + 熔断（`docs/architecture-evolution.md` 第 73 行「已有 solver_guard 多节点支持，只差加节点」）。当前 `IF_CF_SOLVER_URL` 单节点，token 池水位受限于单节点 6.13s/次。

**目标**：扩到 N 节点联邦，token 池水位线性扩展。

**方案探索**：

| 方案 | 描述 | 技术可行性 | 开发成本 | 性能 | 推荐 |
|------|------|-----------|---------|------|------|
| A. 加节点 | `IF_CF_SOLVER_URL` 逗号分隔多节点，solver_guard 已支持轮询+熔断 | 5 | 1h | 线性扩展 | ✅ |

| C. 求解算法优化 | 优化 Turnstile 求解算法 | 2 | 40h+ | 不可控 | ❌ |

**推荐方案 A**：直接加节点，最小改动。

**改动范围**：
- `deploy/.env`：`IF_CF_SOLVER_URL=http://solver1:8001,http://solver2:8001,http://solver3:8001`
- `deploy/docker-compose.yml`：`cf_solver` 服务 `deploy.replicas: 3`（或显式起 3 个服务）

### 6.3 P1-3：adaptive_router 算法升级（Thompson Sampling + UCB1）

**现状**：`api/adaptive_router.py` 用 Epsilon-Greedy-Decay + EWMA 时延 + 熔断（第 1-25 行算法说明）。10% 探索率随机选，不够智能。

**目标**：升级为 Thompson Sampling（贝叶斯）+ UCB1（置信上界），探索更精准。

**方案探索**：

| 方案 | 描述 | 收敛速度 | 复杂度 | 推荐 |
|------|------|---------|--------|------|
| A. Thompson Sampling | Beta 分布后验采样，成功率建模 | 快 | 中 | ✅ 主推 |
| B. UCB1 | $\sqrt{2\ln n / n_i}$ 置信上界 | 中 | 低 | ✅ 辅助（冷启动） |
| C. 保持 Epsilon-Greedy | 现状 | 慢 | 低 | ❌ |

**推荐方案 A+B 混合**：冷启动用 UCB1（样本少时强探索），样本充足后切 Thompson Sampling。

**改动范围**：
- `api/adaptive_router.py`：`ProviderNodeStats` 追加 `alpha=1, beta=1`（Beta 分布参数）+ `total_pulls=0`（UCB1 全局计数）
- 新增 `_select_thompson()` / `_select_ucb1()` 方法，`select_provider()` 内按样本数切换
- 保留现有 `Score=(成功率/log10时延)×负载惩罚` 作为负载感知层（Thompson/UCB1 选出候选后，再用负载惩罚二次过滤）
- 保留 SQLite 持久化（P3-1 已实现，warm 冷启动）

**禁区**：
- 不得改 `record()/record_result()/restore()` 接口（dispatch.py 调用）
- 不得改环形缓冲 1000 条上限
- 保留熔断器逻辑（失败率 >50% 且样本 >=5 → OPEN 30s）

1. **禁止重构公共接口**：函数名/参数顺序/返回结构不得改，只追加新方法。

3. **禁止造轮子**：`storage/`/`background.spawn`/`solver_guard` 联邦/`adaptive_router` 持久化已造好，直接接线。

5. **禁止破坏公益开放**：生图/聊天不限 Key 不得回归。

8. **禁止为通过测试削弱断言**：测试失败改实现，不改测试（除非测试本身错了）。
9. **禁止自动 commit/push/PR**：未经明确指示不执行（`.pre-commit-config.yaml` 强制）。
10. **禁止真实付费上游调用**：预算默认 0，用 Mock/fixture 验证。
11. **禁止 `.sh` 脚本**：Windows 平台用 `node` 或 PowerShell。
