### 0.3 本版核心命题：从「能用/好用」到「自我进化 + 多场景」

v13~v16 解决了「能力走出去」（MCP/聊天回路/画廊/桌面）和「体验闭环」（进度/取消/重试/i18n/主题）。**v17 的三条主线**：

1. **P0 自我进化**：把用户的 DAG 任务/提示词沉淀为自己的 skills（技能闭环），且**安全前置**（技能扫描）+ **黑匣子打开**（教学化）——这是「训练用户自己的 skills」的产品差异化核心（参考项目对标第一梯队：SkillClaw/SkillOpt、CowAgent、learn-agent、SkillSpector）。
2. **P1 多场景扩展**：视频编排化（falai 既有 txt2vid/img2vid 抽象统一 + SSE 逐帧 + DAG 视频节点）、电商/PPT 技能化、记忆三流检索升级（复用已有 `api/vector/VectorStore`）。
3. **P1 体验治理收尾**：i18n 全页面覆盖（10 页缺口）、桌面真机验证欠账清理、启动脚本真实缺陷修复（`desktop/start-desktop.bat` mock/real 参数失效）、MCP 渐进工具暴露、PWA 移动端化。

> 反证前置（Red Team 结论，实施前必读）：技能沉淀**先做手动收藏 MVP、自动沉淀后置**（RT-1）；教学化**先 tooltip 释义、后完整教学层**（RT-2）；视频扩展**先任务模型 + Mock、后接真实 provider**（RT-3）；记忆升级**先 explain、检索融合放 P2 验证**（RT-4）。

## 2. 高优（P0）——自我进化：技能闭环 + 黑匣子打开

> 前置铁律（Red Team RT-1/RT-2 已反证）：**B1（技能四件套 + 技能扫描）必须先于 B2（技能沉淀）**；技能沉淀**先手动收藏 MVP，自动沉淀后置**；教学化**先 tooltip 释义，后完整教学层**。禁止在无扫描的情况下开放任何技能上传/沉淀入口。

### P0-1 技能自动沉淀闭环（手动收藏 MVP → 自动沉淀）

**现状**：`api/skills/` 只有 5 个静态预设技能（critic/ecommerce/image_quality/ppt/prompt_refine），用户 DAG 任务/满意提示词**无法保存为个人技能**；`api/agent/` 无沉淀模块。用户核心诉求「训练用户自己的 skills」未闭环。

**目标**：任何 DAG run 或生成任务，用户可一键「保存为技能」→ 入库待审批 → 生效可复用；后续再做「会话产物 → LLM 摘要候选技能 → 历史 DAG 重放验证（GATE）→ 审批 adopt」的自动沉淀。

**落地步（分两阶段）**：

阶段一（MVP，本版必做）：
1. 新表 `skills(id, name, description, prompt_template, params, frontmatter, source_run_id, status, risk_score, created_at, approved_at)` + `skill_versions(id, skill_id, version, content, checksum, created_at)`（SQLite，复用 `api/db/` 迁移模式）。
2. `api/agent/skill_sediment.py`：`save_from_run(run_id, user_key, name, notes)` 将 DAG run 的输入 prompt/参数/DAG 结构固化为 SKILL.md 格式；`approve/reject/list` 管理函数；写库前**必须过 P0-2 扫描**（`risk_score > 阈值拒绝`）。
3. `api/routes/agent_dag_exec.py`（或新增 `api/routes/agent_skills_admin.py`）暴露：`POST /v1/agent/skills/save-from-run`、`GET /v1/agent/skills`、`POST /v1/agent/skills/{id}/approve|reject`；管理端点走 `IF_ADMIN_KEYS`。
4. `frontend/src/pages/Agent.tsx`：运行结果卡片加「保存为技能」按钮 + 技能管理 tab（列表/审批/删除，空/错/加载三态 + 键盘可达）。
5. MCP `tools.py` 增加 `skills_save`（写意图）与 `skills_list` 扩展，走 `find_tool`/`guard_and_run` 同一护栏。

阶段二（后置，放 P1 或下版）：
6. `skill_sediment_auto.py`：后台对已完结 DAG run 做 LLM 摘要候选技能（预算门禁 `budget_guard.check_can_spend`）→ 历史重放验证（held-out 任务集不降级既有技能效果，`IF_SKILL_GATE_THRESHOLD` 缺省 0.8）→ 待审批队列。
7. 重放验证前先跑最小证伪实验（5 个已知好/坏技能，区分度不足则**保持手动收藏制**，不强行自动沉淀）。

**开关**：`IF_SKILL_SEDIMENT_ENABLED`(0，缺省关)、`IF_SKILL_GATE_THRESHOLD`(0.8)、`IF_SKILL_MAX_DRAFT`(50)。

**验收**：`tests/test_skill_sediment.py`（≥15 用例：save/approve/reject/扫描拦截/预算拦截/版本化/重复名/Mock LLM 重放）全绿；E2E 增段：DAG run → 保存为技能 → 审批 → 在 skills_list 可见。

**风险**：中。私有 prompt 入库泄露（审批页提示、导出脱敏）；命名冲突（唯一索引 + 同名拒绝）；预算消耗（阶段二受预算门禁）。

### P0-2 技能安全扫描（SkillSpector 对标）——开放上传的前置闸门

**现状**：无任何技能内容静态扫描；一旦开放 P0-1 上传/沉淀，第三方法（用户提交的 SKILL.md/脚本）即引入 prompt 注入/数据外泄/提权/供应链投毒风险。**这是 B1 安全前置，必须先立**。

**目标**：`scripts/skillspector.py` 对 SKILL.md/附件做 4 类静态扫描：①prompt 注入（系统指令覆盖/角色越权/分隔符逃逸）；②数据外泄（读取环境变量/密钥/文件路径模式）；③提权与破坏（危险命令黑名单，复用 `is_destructive_command` 逻辑）；④供应链（URL/依赖名/可执行文件）。输出 0-100 风险分 + 命中明细 + baseline 抑制（已知合法模式白名单）。

**落地步**：
1. `scripts/skillspector.py`：纯静态 AST/正则扫描，无网络、无执行；返回 `(risk_score, findings[])`；`--json` 输出供 API 调用；`baseline.yaml` 白名单可配。
2. `api/agent/skill_sediment.py` 与技能上传/沉淀入口统一调用 `scan_skill(content)`：`risk_score >= IF_SKILL_SCAN_REJECT`（缺省 60）直接拒绝入库并记录 `rejected_at`。
3. 管理面 `GET /v1/admin/skill-scans` 报告（最近扫描/风险分布/命中模式），复用 `api/audit.py` 记录扫描动作。
4. `frontend/src/pages/Agent.tsx` 技能审批弹窗展示风险分 + 命中明细（分数高于阈值红色警示 + 二次确认）。

**开关**：`IF_SKILL_SCAN_ENABLED`(1)、`IF_SKILL_SCAN_REJECT`(60)。

**验收**：`tests/test_skillspector.py`（≥20 用例：4 类模式各 5 个正/反例 + baseline 抑制 + JSON 输出 + 阈值拒绝）全绿；用 3 个真实恶意样例验证拒绝。

**风险**：低-中。误报（baseline 持续补充）；绕过（扫描非充分条件，审批 + 审计兜底）。

### P0-3 黑匣子打开 + 教学化引导（CowAgent / learn-agent 对标，先 tooltip 后教学层）

**现状**：`Agent.tsx` 252 行无任何节点释义/教学元素；DAG 图对小白是黑匣子（八类节点 + intent 三路 + critic 无解释）。用户明确诉求「让小白理解产品、使用产品时学习背后原理」。

**目标**：把 DAG 节点/意图/critic 结果转成面向小白的逐步大白话解释。**RT-2 反证结论：不新建双模式 UI，先在现有 DAG 轨迹面板加「节点类型释义 tooltip + 每类节点一屏说明书」，验证点击率后再做完整 learn 模式。**

**落地步**：
1. `api/routes/agent_dag_exec.py`：DAG run 响应/轨迹追加节点级 `explain` 字段（节点类型释义 + 输入/输出一句话说明 + 本步为什么这样规划），由模板生成（**不调 LLM，静态模板零成本**；`IF_AGENT_EXPLAIN_LLM=0` 时用模板）。
2. `frontend/src/components/DagGraph.tsx`：节点 hover/focus 显示 `explain` tooltip（键盘可达、`aria-describedby`）；Agent 页右上角「新手入门」抽屉 = 八类节点一屏说明书 + intent 三段式图解 + critic 是什么。
3. `frontend/src/lib/onboarding.ts`：首次进入 Agent 页的轻量引导（3 步 tooltip 高亮：选场景→填需求→看轨迹），`localStorage[tf-onboard-v1]` 去重，可跳过，无强制弹窗。
4. 教学化文案全部走 i18n（zh/en 同步新增 key，顺带补 G7 缺口）。

**开关**：`IF_AGENT_EXPLAIN_ENABLED`(1)、`IF_AGENT_LEARN_MODE`(0，完整教学层后置)、`IF_AGENT_EXPLAIN_LLM`(0)。

**验收**：`tests/test_agent_explain.py`（≥10 用例：8 类节点 explain 模板全覆盖 + 空 run 降级 + i18n key 一致性）+ vitest 新增 Onboarding/DagGraph tooltip 用例 ≥8；E2E：Agent 页 tooltip 可达 + 抽屉可开。

**风险**：低-中。文案维护成本（explain 模板集中在 `api/agent/explain_templates.py`，按节点类型一条 dict，禁止散落）。

### P0-4 技能工程化四件套（anthropics 官方规范 + 100x-skill-tiktok 对标）

**现状**：5 个技能目录只有 `SKILL.md`（1241~2953 B），无 frontmatter 校验、无 schema、无验证器、无期望结果 → 技能「不可验证、不可测试、不可演进」。

### P1-6 启动脚本真实缺陷修复（2026-09-17 实测发现）

**现状缺陷（`desktop/start-desktop.bat`）**：
1. `set MODE=%1`（mock|real）声明了参数但**从未使用**——launcher 生成固定 `echo set IF_MOCK_UPSTREAM=1`，`start-desktop.bat real` 实际仍是 mock 模式（真实缺陷）。
2. cf_solver 用 `start /b` 拉起后只 `timeout /t 2` 就继续，未做就绪轮询（对比 `start.ps1` 有 30×2s 轮询）→ 冷启动时 healthz 的 cf_solver 状态大概率不健康。
3. healthz 15s 探测失败只有一句话，无 curl 状态/日志尾部，难定位。
4. launcher 临时 bat 写 `%TEMP%\tingfeng-backend-launcher.bat`，多次启动残留（无害但可清理）。

**目标**：修复参数失效 + 对齐 `start.ps1` 的就绪轮询模式。

**落地步**：
1. MODE 生效：`if "%MODE%"=="real" (set IF_MOCK=0) else (set IF_MOCK=1)`；launcher 内 `echo set IF_MOCK_UPSTREAM=!IF_MOCK!`；同时透传 `IF_CF_SOLVER_URL`/`IF_PORT` 等关键 env（从当前环境读）。
2. cf_solver 就绪轮询：`for /l %%i in (1,1,30)` + `netstat :8001 LISTENING` 探测（复用 start.ps1 语义）；超时打印 `deploy\cf_solver\logs\*.log` 尾部。
3. healthz 失败时输出 `curl -s -o nul -w "%{http_code}"` 状态码 + `\v1\healthz` 响应体片段 + `%TEMP%` launcher 内容回显。
4. `start.bat`/`start.ps1` 复查：`start.ps1` 已有 30×2s 轮询（良好），保持不动；补 `--reload` 可选参数（`IF_RELOAD=1`）。

**验收**：`start-desktop.bat real` 启动后 `\v1\healthz` 的 `mock_upstream=false`；`mock` 模式 `true`；冷启动 cf_solver 30s 内就绪；重复启动不残留僵尸 backend（launcher 启动前先 `taskkill` 旧 tingfeng-backend 窗口并按 port 清理）。

**风险**：低。纯脚本修复；改动前备份 bat。

## 9. 红线与注意（机器人必读）

1. **不改已落地勿重做**：v13~v16 全部能力（MCP Streamable、聊天工具回路、画廊管理、i18n、桌面三件套、自升级、进度/取消/重试、归档/导出/预警/健康报告）**只增强不重写**；尤其 P0-1 必须复用 `api/mcp/tools.py` 同一份 `find_tool`/`guard_and_run`，P1-2 复用 falai `_submit_and_poll` 与 v16.1 进度事件模型，禁止复制实现。
2. **付费红线**：所有新增测试 `IF_MOCK_UPSTREAM=1`；技能沉淀/视频/PPT 的 LLM 与上游调用全 Mock；成本预警/健康报告为本地 DB + 快照聚合。
3. **安全前置**：B2（技能沉淀）**必须**在 B1b（扫描）之后；任何技能上传/沉淀入口未过扫描不得开放。
4. **设置工厂测试钩子**：`monkeypatch.setenv` 后必须 `reset_settings()`；config 拆分后旧 import 路径必须完整可用（读包命名空间，勿值拷贝）。
5. **MCP 兼容**：P1-7 的 annotations/新工具**不得破坏现有单端点 JSON-RPC 请求-响应路径**（老客户端与既有调用方）；`include_in_schema` 保持现状。
6. **junitxml 定位法**：本机 Git Bash 吞 traceback，失败用 `--junitxml` 落盘按文件解析。
7. **阻塞 ≠ 完成**：桌面真机自升级/视频真实质量 → 明确标「待验证」，不伪装已过。
8. **不要过度工程**：i18n、归档、导出全部「最小可用闭环」，YAGNI；Redis/Litestream/CDN 等架构演进见 `docs/architecture-evolution.md` 触发条件，当前单机形态勿主动启用；视频扩展本版 **Mock 全链路优先**，动作族抽象只做最小接口。
