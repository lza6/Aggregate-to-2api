### 0.2 已验证事实与铁律（全章引用）

- **付费红线**：真实付费上游调用预算默认 0；所有新增测试 `IF_MOCK_UPSTREAM=1`；新增 E2E/上游交互一律 Mock。
- **版本号全链（约 15 处）**：pyproject.toml(2) + api/main.py + api/mcp/server.py + frontend/package.json + frontend/package-lock.json + landing/package.json + landing/package-lock.json + deploy/pyproject.toml + deploy/docker-compose.yml(2) + desktop/package.json + desktop/src-tauri/tauri.conf.json + desktop/src-tauri/Cargo.toml + README badge + scripts/e2e_v12.py 契约；**frontend/landing dist 必须重建**（openapi 契约测试拦截）。
- **测试五档门禁**：unit（`pytest -m "not integration and not chaos and not slow"`）→ integration（先起 `python scripts/mock_cfsolver.py --port 8001`）→ chaos → slow → E2E（`scripts/e2e_v12.py` 全程 Mock）。
- **本机环境约束（重要，v17 实测沉淀）**：
  1. 前端 vitest 必须 `--pool=threads --testTimeout=20000`（jsdom 慢，forks 池 worker 启动超时）；
  2. pytest 连续大批会被宿主资源监控 kill（exit 137，内存充足但宿主层杀）→ **分批跑（每批 ≤12 文件或每文件独立 subprocess + 断点续跑）**；
  3. `test_edit_mutex.py` / `test_email_pool.py` 两个既有重负载文件在本机被宿主 kill（v16.1 环境通过，与功能改动无交集）→ CI（Linux）需完整口径；
  4. uvicorn lifespan startup 在受限网络可达 ~110s（free proxy/provider 探测超时累计）→ E2E wait_port 用 150s；
  5. E2E 必须每次清 `data/e2e_v12.db` + env 调高 `IF_SOLVE_CIRCUIT_THRESHOLD=10000`（mock solver 不误熔断）。
- **机器人最小改动铁律**：不重写/不重构没坏的文件；新功能一律 `IF_*_ENABLED` 缺省关；新增测试必须覆盖；`monkeypatch.setenv` 后必须 `reset_settings()`（get_settings 缓存语义）。
- **pydantic 2.13 陷阱**：带 `validation_alias` 的字段用字段名构造被忽略（`Settings.__init__` 需用 alias 键或子配置 from_settings 用 alias）——新增配置字段须同步 `deploy/.env.example`（config 双向校验测试拦截）。

### 0.3 本版核心命题：从「手动沉淀」到「自动进化」+「多场景扩展」

v17 解决了技能闭环的**手动基座**（四件套/扫描/沉淀/教学化）。**v18 三条主线**：

1. **P0 自动进化**：技能自动沉淀（重放验证 GATE，RT-1 反证后置项）+ 记忆三流检索（RRF：语义+BM25+超时，复用已有 `api/vector/VectorStore`）+ i18n 全页面 9 页补全（海外可用的硬缺口）。
2. **P1 多场景扩展**：视频编排化（falai 既有 txt2vid/img2vid 抽象统一 + SSE 逐帧 + 前端进度条，Mock 红线）、PPT 可编辑 OOXML 生成、MCP 渐进暴露落地（retrieve/describe 注册 + 新工具审批）。
3. **P2 体验/工程治理**：PWA 移动端、上下文 token 成本优化、前端 a11y 复核、桌面真机验收欠账清理、solver evaluate 参数化、多模态网关长期路线。

> 反证前置（RT-1~RT-4 结论，实施前必读）：自动沉淀**先做最小重放证伪实验**（5 个已知好/坏技能区分度不足则保持手动）；记忆融合**先 explain 已落地，RRF 压测后再上**；视频**先任务模型+Mock 后接真实 provider**；教学化**已用 tooltip 闭环，完整 learn 模式后置**。

## 2. 高优（P0）——自动进化 + 海外可用

> 前置铁律（RT-1 已反证）：自动沉淀**必须**先做「5 个已知好/坏技能重放证伪实验」；区分度不足则**保持手动收藏制**，不强行自动化。B1b 技能扫描已在 v17 落地并有 `scan_skill` 闸门，自动沉淀候选入池前必须过闸。

### P0-1 技能自动沉淀（重放验证 GATE，手动 MVP 的自动化延伸）

**现状**：v17 已闭环「手动收藏 MVP」（`skill_sediment.py` + save/approve/reject + 扫描前置）。自动沉淀（后台对已完结 DAG run 摘要候选技能 → 重放验证 → 审批）未做。

**目标**：把「用户满意的 DAG 运行」自动固化为候选技能草稿，经重放验证 + 预算门禁 + 管理员审批进入「我的技能」。

**落地步**：
1. **最小证伪实验（先行，勿跳过）**：`scripts/sediment_probe.py` 取 5 个已知好/坏技能（好=用户收藏采纳过，坏=评委评分低），对 held-out 任务集重放，比较 `IF_SKILL_GATE_THRESHOLD`（缺省 0.8）区分度；区分度不足 → 输出「保持手动制」结论并停止。
2. `api/agent/skill_sediment_auto.py`：DAG run 终态（succeeded）后，后台对 run 输入/节点轨迹做**预算门禁 LLM 摘要**（`budget_guard.check_can_spend`）生成候选 SKILL.md → `scan_skill` 过闸 → 写 `skills` 表草稿（`source=auto` 标记）。
3. 重放验证器：候选技能在 held-out 任务集上**不降低既有技能效果**才 accept（复用意图评测链路；阈值 `IF_SKILL_GATE_THRESHOLD` 可配、admin 面板可调）。
4. 审批：复用 v17 `/v1/admin/skills/{id}/approve|reject`；前端 Agent「技能管理」tab 展示 `source: auto|manual` + 重放分数。
5. 幂等/防堆积：同 run 只沉淀一次（`source_run_id` 唯一）；草稿上限 `IF_SKILL_MAX_DRAFT`（50）；重复相似名合并提示。

**开关**：`IF_SKILL_SEDIMENT_AUTO`(0)、`IF_SKILL_GATE_THRESHOLD`(0.8)、`IF_SKILL_MAX_DRAFT`(50)、`IF_SKILL_AUTO_BUDGET_USD`(0.0，即默认不烧真实 LLM)。

**验收**：`tests/test_skill_sediment_auto.py`（≥16：摘要预算拦截/扫描拦截/重放区分/幂等/上限/审批联动/Mock LLM 重放）+ 证伪实验报告；E2E：run 完成 → 自动入草稿 → 审批 → my-skills 可见。

**风险**：中。重放分数波动误杀（证伪实验兜底）；私有 prompt 泄露（审批页提示 + 导出脱敏，沿用 v17）；预算（默认 0 烧 LLM 不自动跑，需显式开预算）。

### P0-2 记忆三流检索融合（RRF：语义 + BM25 + 现有排序；先压测后上）

**现状**：explain 已落地（v17 B4），但 `MemoryStore.query()` 仍是 `ORDER BY importance DESC, last_accessed_at DESC`（`api/agent/memory.py`）；`api/vector/VectorStore`（`api/vector/store.py:72`）已存在（intent embedding 在用），**零新依赖可复用**。

**目标（RT-4：先压测再上）**：三流融合——语义 topk（复用 VectorStore）+ SQLite FTS5 BM25（内置免依赖）+ 现有 importance 排序 → **RRF 融合**；`explain` 扩展为「为什么这条命中」（融合分来源权重）。

**落地步**：
1. 压测基准（先行）：`scripts/bench_memory_rrf.py` 造 1000 条记忆（临时库），对比纯 SQL vs RRF 检索延迟（目标：P95 < 50ms）与召回（hand-picked 查询集）。不达标 → 记录结论不上线，保持纯 SQL + explain。
2. `api/agent/memory.py`：`_ensure_fts()` 建 FTS5 虚表（`mem_atoms_fts`）+ 同步触发器（INSERT/UPDATE 幂等）；`_rrf_merge(rankings, k=60)` 纯函数；`query(mode="rrf"|"plain")` 双模式（`IF_MEMORY_RRF=0` 缺省纯 SQL 零回归）。
3. 语义路径：`api/vector/embed.py` 现有 embed + VectorStore topk（`IF_MEMORY_RRF_VECTOR=1` 时；embedding 不可用降级双流）。
4. 列：`mem_atoms` 已有 `last_accessed_at`；新增 `access_count INTEGER DEFAULT 0`（ai-memory 衰减数学化用，`IF_MEMORY_APPLY_DECAY=1` 时参与）。
5. 结果 explain 补充：「语义命中 top5 / 关键词命中 / importance 加分」来源权重。

**开关**：`IF_MEMORY_RRF`(0)、`IF_MEMORY_RRF_VECTOR`(1)、`IF_MEMORY_APPLY_DECAY`(0)。

**验收**：`tests/test_memory_rrf.py`（≥20：FTS 同步/一致性、RRF 纯函数、双模式等价、衰减、降级、压测断言）+ 回归 supersede/agent_memory 全绿。

**风险**：中（SQLite FTS5 热路径压测；存量数据零迁移——FTS 虚表可重建、access_count 加列幂等）。

### P1-2 PPT 可编辑产物生成（OOXML，ppt-master 对标）

**现状**：`api/skills/ppt/` 已补四件套（SKILL.md + schema/validate/expected_results，v17），但**只有大纲**（无 .pptx 产物）。用户显式扩展诉求「PPT 可编辑文件」。

**目标**：`generate_pptx.py` 把大纲 JSON 渲染为可编辑 OOXML PPTX（零浏览器依赖；模板体系 + 网页预览后置）。

**落地步**：
1. `api/skills/ppt/generate_pptx.py`：OOXML 最小实现（`[Content_Types].xml` + `_rels/` + slide XML 模板，纯 stdlib `zipfile`；**先查依赖**——python-pptx 若可加为轻量依赖则优先，避免手写 OOXML 维护成本；不可加则 stdlib 直写最小版：标题/要点/配图占位）。
2. 输出 `file_id` 落画廊/文件存储；DAG ppt 节点产物链接 `GET /v1/files/{file_id}`（若画廊下载端点不够，最小补一个）；`IF_PPT_GENERATE`(0) 缺省关。
3. 前端 Agent 页技能卡「下载/预览」入口（文件头 `PK` 校验 + 大小）。
