## 二、P0 阻塞问题修复清单

### P0-A: 非 imagefree 提供商 inflight 永久泄漏【后端·最高优先】

**根因**：`_dispatch_generate()` 和 `_dispatch_edit*()` 中非 imagefree 路径的 `_run()`：

```python
# dispatch.py:234-266（dispatch_edit.py:168-197、211-240 同构）
async def _run() -> None:
    try:
        res = await provider.generate(...)        # 成功/失败都走 record_result
        ...
    except Exception as e:
        await db.mark_finished(...)               # ← 只落库，不 record_result
        log.exception(...)                        # ← inflight 永久保留
```

而 `registry.provider_for()` 内部（registry.py:109 → `adaptive_router.select_best()` → `_record_inflight_locked`）已给该 provider 的 `in_flight_requests` +1。唯一 -1 的路径是 `record_result()`，此处异常分支不调用 → 泄漏。

**修复**（三处同步改）：
```python
except Exception as e:
    await db.mark_finished(task_id, "error", None, str(e), time.monotonic() - t0)
    try:
        registry.adaptive_router.record_result(provider.prefix, (time.monotonic() - t0) * 1000.0, False)
    except Exception:
        pass
    log.exception("提供商生成异常 %s", task_id)
```

**同理** `dispatch_edit.py:191-193`、`dispatch_edit.py:234-236`。

**验证**：
```python
# 新增测试：inflight 在异常路径后回落
with mock.patch.object(provider, "generate", side_effect=TimeoutError):
    await _dispatch_generate_fail_case(...)
    assert router.node_snapshot()[prefix]["in_flight_requests"] == 0
```

### P0-B: 非 imagefree 无上游并发管控【后端】

**根因**：非 imagefree 直接 `asyncio.create_task`，不经过 `Engine` 队列限流。

**修复**：为后台直调增加 `asyncio.Semaphore` 上限（复用 `semaphore_manager.upstream_semaphore`，或加独立 per-provider semaphore）：

```python
# dispatch.py 顶部
provider_semaphores: dict[str, asyncio.Semaphore] = {}
def _provider_sem(prefix: str, limit: int = 16) -> asyncio.Semaphore:
    if prefix not in provider_semaphores:
        provider_semaphores[prefix] = asyncio.Semaphore(limit)
    return provider_semaphores[prefix]

# _run() 内
async with _provider_sem(provider.prefix):
    res = await provider.generate(...)
```

**验证**：并发 100 个请求打向单 provider，实际在途 ≤ limit。

### P0-C: Dockerfile.cfsolver 构建路径错误【部署】

**根因**：`deploy/docker-compose.yml` 中 cfsolver 的 `build.context: .`，但 `COPY cf_solver/...` 的目录实际在 `deploy/cf_solver/`。

**修复（方案 A，推荐）**：
```yaml
# deploy/docker-compose.yml
cfsolver:
  build:
    context: ./deploy
    dockerfile: Dockerfile.cfsolver
```
`Dockerfile.cfsolver` 内 COPY 路径不变（`./cf_solver/requirements.txt` 相对 context 的 `deploy/cf_solver/`）。

**验证**：`docker build -f deploy/Dockerfile.cfsolver -t imagefree-cfsolver:test deploy/` 成功。

### P0-D: test_providers.py 与 minimaxh3 移除不同步【测试】

**根因**：`registry.bootstrap()`（registry.py:283-296）已移除 minimaxh3，但 `tests/test_providers.py` 仍有 8 个用例断言 `registry.providers["minimaxh3"]`（KeyError）。

**修复**：
- 删除/改写 8 个 minimaxh3 专属用例（`TestProviderGenerate.test_minimaxh3_*`、`test_provider_summary` 断言列表）
- `test_provider_summary` 的断言改为 `{"imagefree", "aifreeforever", "nanobanana"}`

**验证**：`pytest tests/test_providers.py -q` 全绿。
