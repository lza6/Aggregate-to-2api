## 1. 高优（P0）——先把 v12.0.2 遗留闭环 + 基础体验补齐

### P0-1 审批收件箱 SQLite 持久化（v12.0.2 遗留）

**现状**：`api/agent/human_inbox.py` 为进程内 dict + threading.Lock，重启即丢；发行说明已留 v12.0.2 候选。

**目标**：审批请求持久化到 `data/human_inbox.db`（独立小库，仿 `api/agent/memory.py` 的 `MemoryStore` 模式：同步 `sqlite3` + threading.Lock，db_path 可注入），重启后可查历史审批。

**落地步**：
1. `HumanInbox.__init__(db_path: str = "data/human_inbox.db")` 注入；`_init_schema()`（表 `inbox_requests(req_id PK, run_id, node_id, prompt, status, note, created_at, decided_at)`）在首次 write 前初始化（**禁止 `__init__` 里 asyncio.run** —— 参照 Do-Not-Repeat#3）。
2. `create/decide/wait/get/list` 保留内存缓存（热路径）再落盘；`reset()` 清内存+清表。
3. 模块单例 `human_inbox = HumanInbox()` → `get_human_inbox()` 工厂 + 测试钩子 `reset_human_inbox()`（仿 config 工厂，conftest 每用例隔离）。
4. 测试：`tests/test_human_inbox_persist.py`——创建→decide→**重启实例**（新 HumanInbox 同 db_path）→list 仍可见；并发写不会锁死；reset 清空。

**验收**：`pytest tests/test_human_inbox_persist.py -q` 全绿；重启前后 `GET /v1/agent/human-inbox` 历史可查。
**影响半径**：L2（多文件但隔离回滚）。

## 2. 高优（P0）——DAG 编排层（当前最大能力缺口）

> 现状：`api/vector/` 已有真实 embedding（`compute_embedding`，hash 桶 + cosine）+ `VectorStore`（`similar_search/find_duplicate`）+ `GET /v1/gallery/similar`；`api/skills/` 技能索引（ecommerce/ppt/critic/image_quality/prompt_refine）+ `/v1/agent/skills` 端点。gap 全在编排层。

### P0-5 DAG 编排接入 memory 存储 + 检索增强（把"记忆"变成真链）

**目标**：`_exec_memory` 节点（现为记忆写/读占位）→ 复用 `api/agent/memory.py` 的 `MemoryStore`（L1 核心记忆 + L2 概要 + L3 反思，带 `consolidate()` 巩固）；DAG 增加 `rag`/`retrieval` 节点复用 `api/vector/store.py` 的真实 `similar_search`（当前 `kind in ("retrieval","rag")` 只返回占位）。

**落地步**：
1. `agent_dag_exec.py:_exec_memory` 增 `op` 参数（read/write），write 调 `MemoryStore.observe`、read 调 `observe_memory` 同款 `query`；scene 取 intent 结果。
2. `_exec_rag` 现转发到 `_exec_retrieval`（`agent_dag_exec.py:76-77`）——把 `_exec_retrieval` 从"占位串"改为：`VectorStore.similar_search(task_id, top_k)` / 按 prompt 计算 embedding 后 `find_duplicate`；无本地向量库时降级占位并 log（不崩 DAG）。
3. 前端黑匣子面板在文本 end 显示记忆写入条数与相似命中（顺带让"记忆/检索"节点可见）。

**验收**：单测 `tests/test_dag_memory_chain.py`：write→read 同 scene/user_key 命中；`retrieval` 节点走假 VectorStore 命中后 result 含 top_k 条；开关 `IF_DAG_STORE_BACKEND=sqlite` 全程回滚安全。
**影响半径**：L2（编排层纯增量）。

### P0-6 intent embedding 双路（接入既有 `api/vector/embed.py`）

**目标**：intent.py 头注释已声明"embedding + LLM 双路"，现在只有规则+LLM。补：规则未命中时先用 `compute_embedding(prompt)` + 预置意图向量（image/video/chat/ecommerce/ppt 5 类原型 prompt 离线算好）算 cosine，得分 ≥0.7 直接返回（零成本零延迟），<0.6 才走 LLM。

**落地**：`intent.py` 增 `_embed_classify(prompt) -> IntentResult | None`，阈值常量走 config（`IF_INTENT_EMBED_THRESHOLD`）；`classify_intent` 顺序：规则 → embedding → LLM。
**验收**：新增 `tests/test_agent_intent_embed.py`：5 类代表 prompt 双路命中 scene 正确；embedding 不可用（cosine 低于阈值）时回退 LLM/Mock 路径不崩。
**影响半径**：L2。

### P0-7 DAG 持久化运行轨迹 + 断点续跑/回放

**现状**：`api/routes/agent_dag_store_sqlite.py` 已有 run 落库（`dag_runs.db`），但节点级执行轨迹未存、无续跑。

**目标**：在 `execute_run` 每节点终态时经 `DagRun.public_state()` 快照增量落 `node_traces` 表（node_id/status/result/error/attempt/duration/condition）；重启后 `GET /v1/agent/dag/{run_id}` 能重建完整轨迹；新增 `POST /v1/agent/dag/{run_id}/resume`（从 failed/skipped 节点重试，幂等：已有 succeeded 节点跳过）。

**验收**：单测 `tests/test_dag_resume.py`：构造中途 failed 的 run → resume → 终态 succeeded 且不重跑 succeeded 节点；DAG 页刷新后轨迹不丢。
**影响半径**：L2。

3. **设置工厂测试钩子**：`monkeypatch.setenv` 后必须 `reset_settings()`（memory 踩坑#1）。
4. **版本门禁**：bump 后重建 dist（让 openapi 契约测试通过），`rg 旧版本号` 清残留。
5. **junitxml 定位法**：本机 Git Bash 吞 traceback，失败用 `--junitxml` 落盘按文件解析（memory 踩坑#3）。
6. **阻塞 ≠ 完成**：Rust 缺失/浏览器视觉验证装不上 Playwright → 明确标"待验证/阻塞"，不伪装已过。

8. **提交与发布**：未经明确指示不 commit/push；完成后按版本全链 bump + dist 重建 + verification-log 追加 + 发版说明（如用户要求）。
