从第一性原理出发，**ImageFree 并非单纯的 API 网关，而是一个“不确定性消除引擎”**。它的核心价值在于：通过前端极致交互感知 + 后端高度弹性的账号自愈与队列调度，将上游不稳定的底层免费资源，包装成对外 99.9% 可用性、秒级响应的稳定 SaaS 级图像生成服务。

### 2.2 核心模块边界定义与接口契约

1. **`api/dispatcher/` 任务调度域**：专职处理任务进队、排队优先级、超时降级与死信（DLQ）重试，绝不直接调用上游网络请求。

## 三、后端高可用与算法优化实施细则 (Backend & Algorithm Deep-Dive)

### 3.1 账号与令牌池自适应调度算法 (Adaptive Load-Balancing & Health Scoring)

#### 原理剖析与算法设计
传统的简单轮询 (Round-Robin) 或随机挑选会导致“雪崩效应”：当某个账号触发上游限流或响应变慢时，依然会被持续分配流量，从而拖垮整个 Worker 流水线。

**v4.0.0 引入：自适应动态评分选择器 (Adaptive Epsilon-Greedy MAB)**
- 每个账号维护一组实时状态：
  - $\text{Score} = w_1 \cdot \text{SuccessRate} + w_2 \cdot \frac{1}{\text{EMA\_Latency}} - w_3 \cdot \text{ConsecutiveErrors}$
  - $\text{EMA\_Latency}_{t} = \alpha \cdot \text{Latency}_{new} + (1-\alpha) \cdot \text{EMA\_Latency}_{t-1}$ （平滑响应时间）
- **选号策略**：
  - 90% 概率选择当前综合得分最高的健康账号。
  - 10% 探索概率分配给正在冷却恢复的账号以探测其可用性。
  - 遇到 `429 Too Many Requests` 时，立即退火并将其置入指数退避衰减桶（Backoff Bucket）。

```python
# 设计伪代码参考 (可在 api/account_pool.py 中落地)
class AdaptiveAccountScore:
    def __init__(self, email: str):
        self.email = email
        self.ema_latency_ms = 1000.0  # 初始预估 1s
        self.success_count = 0
        self.fail_count = 0
        self.consecutive_errors = 0
        self.in_flight_requests = 0

    def update_result(self, duration_ms: float, is_success: bool):
        alpha = 0.2
        if is_success:
            self.ema_latency_ms = alpha * duration_ms + (1 - alpha) * self.ema_latency_ms
            self.success_count += 1
            self.consecutive_errors = 0
        else:
            self.fail_count += 1
            self.consecutive_errors += 1
            self.ema_latency_ms *= 1.5  # 惩罚提升
```

### 3.2 邮箱池多源高并发注册与降级熔断 (Multi-Source Resilience)

#### 痛点
上游会对频繁注册的临时邮箱域名实施风控（例如阻断邮件发送或要求更复杂的 Turnstile）。
#### 解决方案
1. **多源动态适配层**：统一 `BaseEmailSource` 抽象接口，标准化 `fetch_mails()`、`extract_verify_link()`、`health_probe()`。
2. **邮箱域名风控实时反馈机制**：一旦某个源连续 3 次拉取不到邮件，自动标记该域名池处于“冷却观察态”，自动降级至备用源（如自建邮件网关/备用临时邮箱 API）。
3. **预生成缓冲池 (Pre-warmed Token Buffer)**：保持后端始终有 20~50 个**已激活、已通过 Turnstile 校验的高可用预热账号**，当外部请求洪峰来临时，从预热池秒级取出，完全消除“边生成边注册”的链路等待延迟。

### 3.3 SQLite WAL 高并发极限压测优化与轻量级无锁化设计

#### 核心调优参数与连接治理
```sql
-- 初始化 SQLite 时强制启用的超高性能配置参数
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;        -- 兼顾断电安全与极致写性能
PRAGMA busy_timeout = 10000;        -- 锁等待超时增至 10 秒，避免 busy 报错
PRAGMA cache_size = -64000;         -- 分配 64MB 内存缓存
PRAGMA mmap_size = 268435456;       -- 启用 256MB 内存映射 I/O
PRAGMA temp_store = MEMORY;         -- 临时表全部常驻内存
PRAGMA wal_autocheckpoint = 1000;   -- 合理触发 WAL Checkpoint
```

#### 读写彻底分离模式 (Read/Write Separation)
- **写连接**：全局严格单例（Single Dedicated Writer Connection），由专职队列/线程处理写入，消除任何写锁争抢。
- **读连接池**：多连接池化分配（Connection Pooling with `autocommit=True`），各 Worker 并发读取无任何等待。

### 3.4 异步生成流水线、死信队列 (DLQ) 智能自愈与背压机制

1. **背压控制 (Backpressure)**：当队列深度达到预设阈值（如 > 200 个任务）时，HTTP 接口直接返回 `429 RateLimitExceeded` 并附带建议重试时间 `Retry-After`，保护底层 Worker 不被压垮。
2. **DLQ 智能分类重试器 (Smart DLQ Reclaimer)**：
   - 区分**可重试错误**（网络超时、上游 502/503、账号被限流）与**不可重试错误**（Prompt 违规拦截、参数非法）。
   - 可重试任务自动由后台自愈协程按指数退避调度重试，最大重试 3 次后才彻底归档。

### 4.2 极简小白模式 (Novice Mode) vs 专业参数工作台 (Pro Studio)

- **极简模式 (Novice Mode)**：
  - 只有一个大提示词输入框 + 一键“✨ AI 优化提示词”。
  - 视觉化预设卡片：**赛博朋克 / 3D吉卜力 / 超写实人像 / 极简国风 / 电影质感**。点击卡片自动注入最佳 Prompt 修饰词与长宽比。
- **专业模式 (Pro Studio)**：
  - 展开高级控制栏：Negative Prompt（负面提示词）、Seed 控制、Sampler 策略、批量并发数量（Batch Count 1~4）。
  - 支持参数历史记忆与一键导入预设。

### 4.3 批量并发生成、画廊瀑布流虚拟化与富媒体资产管理

1. **虚拟化瀑布流 (Virtual Scroll Grid)**：
   - 当画廊累积 500+ 张图片时，前端若全量渲染 DOM 会导致掉帧与内存泄漏。
   - 引入虚拟列表（Virtualization），仅渲染视口范围内的图片卡片，保证万张图片流畅 60fps 滚动。
2. **图像高清灯箱 (Lightbox & Zoom Comparison)**：
   - 点击支持无级缩放查看细节。
   - 提供快捷导出（PNG / WebP）、去除元数据、生成分享链接功能。

### 4.4 实时任务观测台与 WebSocket/SSE 零轮询感知

- 彻底淘汰前端 `setInterval` 500ms 短轮询机制。
- 引入 **Server-Sent Events (SSE)** 或 **WebSocket** 链路：
  - 前端发起生成后保持连接，服务端在任务状态流转（`queued` -> `processing` -> `completed`）时主动 Push 结构化事件。
  - 大幅降低 Nginx 与 FastAPI 的 HTTP 握手开销，减少 80% 无效网络请求。

## 五、端到端 TDD 质量保障与全链路测试方案 (100% Quality & Testing Strategy)

### 5.1 单元测试、隔离桩与无污染 Mock 规范

根据项目历史记忆与真实工程经验，**严格杜绝全量测试污染与假绿**：
1. **全局隔离原则**：
   - 严禁在测试中对全局单例对象直接赋值。必须统一使用 `monkeypatch` / `unittest.mock`。
   - 环境变量注入严格限制在 fixture 内，测试结束后还原。
2. **测试用例全覆盖矩阵 (100% Core Matrix)**：
   - `test_adaptive_router.py`：测试各种响应时间与错误率下的 MAB 路由收敛性。
   - `test_email_source_failover.py`：测试邮箱源逐级故障转移与熔断恢复。
   - `test_db_wal_concurrency.py`：模拟 50 并发协程同时读写 SQLite，断言零锁死、零数据丢失。
   - `test_dlq_backpressure.py`：测试队列满载时的拒绝策略与死信补偿。

### 5.2 核心并发链路集成与混沌工程测试 (Chaos Testing)

编写专职混沌压测套件 `tests/test_chaos_resilience.py`：
- **场景 A**：模拟上游 80% 请求随机返回 429 与 504，验证系统是否平滑重试并成功交付。
- **场景 B**：模拟 SQLite 写入瞬间产生 1 秒 IO 挂起，验证内存任务缓冲是否有效承托不丢单。
- **场景 C**：模拟网络瞬间抖动中断，验证 SSE/WebSocket 自动重连机制。

### 5.3 E2E 浏览器自动化与视觉回归矩阵

- 利用 Playwright 编写端到端关键链路：
  1. 首页加载 -> 模式切换 -> 提示词输入 -> 点击生成 -> 骨架屏出现 -> 进度流转 -> 图像渲染成功呈现。
  2. 历史画廊翻页与筛选 -> 灯箱打开 -> 批量下载操作。
  3. 响应式布局测试：375px（移动端）、768px（平板）、1440px（桌面端）视觉无错位、无横向滚动条。
